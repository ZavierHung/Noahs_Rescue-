# 一键试玩与图片 UI 迭代

## 最快进入游戏

本地服务已运行时，打开 <http://localhost:3000/mobile>，点击 **一键测试开局** 即可。无需先选六人同屏，也无需再点击六次准备或一次开始。页面会显示连接、入场、准备、开局的进度，完成后显示六个可操作手机。

尚未启动服务时，在项目根目录运行 `npm run dev:mock`，再打开上述地址。这个启动方式不调用真实模型。若已有服务占用端口，请先在原终端停止原服务，不要重复启动。

原生小程序同样提供该按钮，开局后在顶部测试面板切换六个角色。浏览器可切换为单人手机逐个操作，或六人同屏。

## 正常使用与安全边界

- 再次点击：继续本端未结束的测试局，保留分数和审判记录，不重新开局。
- 结束本局后再点击：新建一局；旧局继续保留在历史记录。
- 部分加入或准备失败：显示失败原因，重试会补齐原等待室，不自动新建第二局。
- 开局响应丢失：重试读取权威状态，已开局则重连，不重复执行开始指令。
- 返回手动游戏：恢复原来的身份，不清除、结束或改动原手动游戏；测试局也继续保留。
- 自动安排只走建房、加入、准备、开始，不会自动触发上帝、汇报或结算。上帝核心流程、人设数据后端、RAG 和人工确认奖惩不变。
- 一键开局本身不消耗 LLM 额度。开局后手动触发上帝是否调用 M3，取决于运行中的后端配置；需要全程免费本地规则测试时使用 `dev:mock`。
- 测试身份不是 AI 玩家，不会自主下棋、编写汇报或决定分数，仍由使用者轮流操作。

测试房间与普通房间都存入服务端 `server/data/rooms.json`，记录页均可查看；“独立”指身份与房间隔离，不是另一套数据库。浏览器与微信存储空间不同，不会自动共用测试凭证。清空浏览器/微信存储会丢失旧身份，不要在需要恢复旧测试局时清除。

0.2.0-alpha.1 已补上持久化建房请求 ID。即使**创建请求本身**已写入服务端但响应丢失，客户端重启后仍会续用原请求，恢复同一局；服务端重启也能识别重试。旧调用方未传 `requestId` 的请求仍按原逻辑创建。跨标签页同时发起两个不同请求仍可能创建两个房间，请避免同一浏览器多标签同时安排测试局。

## 模块边界与迭代点

`miniprogram/shared/quick-game.js` 是共享开局编排层，供浏览器和小程序复用。它创建六个短生命周期的 `createClient`，使用 `noah-quick-A01` 至 `noah-quick-H03` 存储凭证；不增加服务端作弊入口，不直接写 JSON。完成或失败时销毁控制器，防止继续轮询。

UI 层负责按钮禁用、进度、切换到测试身份、切回手动身份。重新安排测试局时先卸载/暂停当前测试控制器，避免旧轮询将新房间 ID 写回旧值。浏览器按钮在事件处理准备就绪后才启用，避免刷新后第一次点击无响应。

图片在 `miniprogram/assets/` 与 `app/public/images/` 各有一份同名本地文件，自动测试校验内容一致；替换素材时同步两处文件。两张图合计 487,291 字节，未引入外部图片域名、额外模型密钥或图片 SDK。图片只表达方舟/神谕氛围，不替代随机上帝的真实人设名称。生成方式与完整提示词见 [素材说明](ART_ASSETS.md)。

## 一条命令回归

首次安装依赖：`npm ci` 和 `npm --prefix app ci`。之后：

```bash
npm run test:quick  # 8 个快速开局接口/控制器测试 + 3 个 Chrome 场景
npm run check:all   # 完整自动测试、类型检查、构建、浏览器测试
```

测试使用隔离临时 HTTP 服务、实际游戏模块与临时 JSON 文件，不读取真实 `.env`，不修改用户存档，也不调用真实 M3。浏览器测试会复用本地前端服务，但将 API 请求转发到隔离测试服务。

本轮新增覆盖：六人真实开局、手动游戏保留、重复点击续接、部分加入/准备失败、开局响应丢失、结束后新建、断网不建房、同页面并发激活保护、原生角色切换/手动身份恢复，以及图片本地打包和一致性。真实浏览器覆盖刷新续接、图片加载、390px 页面无横向溢出、六个手机进入新房间。

产品化新增覆盖建房响应丢失后的恢复。正常玩家入口为 `/play`，不展示一键模拟按钮，和测试身份分开；此前的测试结果作为历史迭代保留，最新验收见 [发行路线](RELEASE_PLAN.md)。

尚未完成微信开发者工具编译或真机验收。原生测试执行实际页面逻辑并模拟微信平台调用，不能等同于微信运行时实测。
