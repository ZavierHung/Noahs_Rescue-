# 网页地图版：快速试玩与模拟

当前开发分支 `feature/student-learning-iterations`，版本 `0.4.0-local`；已保存的基线在 `main@c32f6d3`，小程序在 `archive/miniprogram-v0.2`。新开局自动使用学习版本，旧存档不强行迁移。

## 一分钟开局

先看首页「游戏核心目标」。卡牌悬停或键盘聚焦显示本版效果，Esc 关闭；手机点击卡图查看长规则。原卡面可能保留旧文案，以本版规则为准。

1. 在根目录运行 `npm run dev:mock`；首次先执行 `npm ci`、`npm --prefix app ci`。
2. 打开 [localhost:3000](http://localhost:3000/)。
3. 默认已选 3 人；点击玩家标签切换配置，从 10 张角色卡中选人，再点地图旗子选择出生地。
4. 点击“确认角色与旗子 · 开始航程”。同一台电脑依次操作不同玩家。
5. 当前玩家依次出牌、移动、采集、上交。绿色格子表示合法目的地；每个步骤都可跳过。
   学习 v2 的第 2、4、6 轮开始会出现一次公共二选一，指定玩家点一个方案后恢复正常行动；每局仅三次。收益／代价直接列在按钮上，公共收益不计个人捐赠。
6. 第 3、5、7 轮末逐人确认洪水损失。第 8 轮末撤离与生存结算后，全员（含未存活者）轮流互评或明确跳过；再初审，幸存者逐人申辩或放弃，最后敲定名单。页面分开显示共同成果、个人行为事实和船位，不把落选当道德失败。

`dev:mock` 不使用真实模型。需要已有 M3 配置时用 `npm run dev`；模型只在终局审判/申辩时调用。已有服务占用端口时不要重复启动。

刷新恢复本局；返回选人不会删除历史。“全局航程日志”“方舟捐赠记录”和“初判与逐人交互留档”可追溯行为。卡面点击放大，Esc 关闭。建议新开一局体验新版数值，旧局不会重置。

## 邀约共同领取（不是交换）

1. 点击邀约卡的“使用”，自动定位到独立邀约面板；双方零库存也可以使用。
2. 从以发起者为中心、地图直线距离最近的两名其他玩家中选一人；同距离按座位号排序，不限相邻一格。
3. 发起者选择自己想获得的一种资源，点击“发送邀约”。
4. 系统切到受邀者，对方独立选择想要的一种资源，然后“接受邀约并领取”或“拒绝”。
5. 接受后双方各新增一份，不从任何一方扣除；消耗发起者邀约卡。拒绝不发资源、不消耗卡，可重试。刷新恢复请求，只读查看不能代为回应。

互助信标独立保留旧交易规则：同格/相邻一格，双方各交出一份现有物资，经同意后交换。卡面图片仍是原图，最新执行规则会另外显示，覆盖原图旧版邀约文字。

## 操作错了：撤回与重做

1. 在页面顶部「行动修正」点「撤回上一步」，核对回合、玩家及操作，再点「确认撤回」。取消或 Esc 不改动游戏。
2. 支持最近 20 步，可跨回合、跨玩家；必须由当前行动/响应玩家确认。查看其他玩家时只读，先返回当前行动玩家。
3. 会整步恢复资源、卡牌、位置、世界分数、洪水及待响应流程。例如撤回已接受的邀约，会返还卡牌、回退双方新增资源，并重新等待受邀者回应。
4. 可以「重做」恢复原结果；抽牌、骰点不会重抽。撤回后做出新操作，原来的重做路线关闭。刷新、重启保留历史；旧局仅能撤回更新后新记录的操作。
5. 「撤回与重做记录」显示修正留档。被撤回的行为不计入有效日志、捐赠贡献或上帝判断；导出 JSON 包含独立修正记录。
6. 学习局在**第一份互评／跳过提交后锁定**；旧局在初判后锁定。不能看完评价再改行为，不能撤销发言、重新洗牌或改最终名单。

这是本地共用的整局修正工具，不是每人私有的撤回记录；竞技联网版本还需多人同意机制。

## 洪水缴纳

第 3、5、7 轮末自动出现蓝色洪水结算面板。首先查看方舟的骰点、应扣及已实际扣除数量；这部分已经完成，不会随个人确认重复扣除。

然后逐人查看“固定扣除”和“额外选扣”，点击一种资源图标，核对“本次实际缴纳合计”，最后点击确认。库存不足只扣现有物资，储备仓减免自动显示；没有可扣物资也需确认后交给下一位玩家。面板可展开已缴纳玩家的实际损失。

欠缴每份积累 1 点伤势。终局受困者可最后向内移动 1 格；随后个人种子自动消耗，每份恢复 1 点伤势。必须位置安全且剩余伤势不超过 5 才算幸存。保留种子用于救生与捐给方舟之间需要取舍。

## 容量和登船审议

方舟每存有 17 份物资支持 1 人（四种资源各算一份），向下取整，最多本局人数且不超过 6；空船容量为 0。洪水扣库会降低容量，不会抹掉历史捐赠贡献。

上帝读取完整行为、人设及本地知识后先给初步名单；每位幸存者按座位顺序发言或明确放弃，上帝逐人回应，期间名单仍是暂定。全员完成后点击“完成交互，请上帝敲定最终名单”。不能批准未存活者或突破容量；不会触发新灾难、扣款或死亡。离线模式仅保存发言并按日志复核，不假装理解自由文本；M3 模式会收到全部对话。

展开「本阶段学术依据与行为分析」可看中文结论、局限、行为关联和原文。每次申辩都会重新检索，历史记录保留当时材料。「规则与本地约定 → 学术文献目录」列出全部 22 份，含 11 本教材与 1 份课程指南，可查看版次、概念及适用边界。同书章节不重复计数；教材观点并非唯一的登船答案。

本机已归档 13 份 PDF，曼昆为配套讲义、Perman 为样章，并非整本教材；另 8 个网页章节及 1 个大型 PDF 只保留外部链接。原件未加入 Git，新机器运行 `npm run knowledge:archive`；使用系统代理时改用 `npm run knowledge:archive:proxy`，脚本跳过外链条目，不误报下载失败。检索冒烟测试：`npm run test:knowledge`（51 条中英文用例）。完整目录与出处分析见 [学术知识库报告](ACADEMIC_KNOWLEDGE_REPORT.md)。

真实 M3 测试需主动运行 `npm run test:knowledge:live:proxy -- --live`（直连去掉 `:proxy`），最多两次付费/套餐请求，只使用内存中的六人模拟，不改实际对局。模型 ID 为 `MiniMax-M3`；旧配置 `MiniMax-M3.0` 会自动兼容，无需重新填写 Key。代理启动器只继承当前系统手动 HTTP(S) 代理或已有环境变量，需要支持 `--use-env-proxy` 的 Node。开发服务需要代理时用 `npm run dev:proxy`，不要与已运行的服务同时启动。

## 查看其他玩家（不会换回合）

- 点击地图下方任意玩家卡，右侧显示该玩家的手牌、已生效科技、资源、累计捐赠和世界影响。点击卡面可放大。
- 非当前玩家只读，不能出牌、弃牌、移动、采集、捐赠或更改世界分数；顶部仍显示真正的当前行动者。
- 点击“返回当前行动玩家”继续游戏。普通模式自动跟随行动顺序；交易/灾难/洪水由系统指定的玩家回应。
- 切换查看不保存游戏、不推进回合；尚未提交的操作输入会清空，刷新后回到当前行动者。仍为本机轮流模拟，不是新增账号登录功能。

## 快速验证共享分数与灾难

1. 新局找到“共同的世界”。经济、环境、社会是全员共享的数值，不随当前玩家切换。
2. 展开“主持／实验模式”，把经济滑条拖到 18，填写原因，点“应用世界分数并结算灾难”。拖动不提前发奖或扣分；主持调分不计个人贡献，并可能使本局生态归因不可评。
3. 查看“先发展再治理”和“财富悬殊”同时出现；环境、社会各减 1。根据响应玩家逐人领取一份资源，之后自动结算最穷者向最富者转移金属。
4. 经济 18 改为 19 不再重复触发；降到 17 只解除极高卡。降到 2 则叠加“经济萧条”和“通货紧缩”。
5. 环境设为 17，在地图选一个资源格，填写保护情况，点击“确认成功保护”，环境变 18，两张环境卡共存；社会显示持续修正 −1。这里只确认实际条件，不自动把普通采集当保护。
6. “全局航程日志”可以核对手动原因、原值/结果和每次灾难影响。刷新不会重复执行效果，结算中的资源选择也会恢复。

需要先完成当前卡牌、灾难或洪水选择才能手动调分。生态管制在场时，降低环境的科技会先请求有资源的邻居选择“支付并阻止”或“放行”。保障物资可选四类资源，晶矿按金属；完整规则见 [disaster.md](../disaster.md)。

## 一条命令模拟

```bash
npm run test:simulation       # 20 局
npm run test:simulation -- 100
npm run test:simulation -- 20 --learning # 六人互评到终判完整离线闭环
npm run test:learning                    # 学习规则 mixed 策略 20 局
npm run test:balance -- --matches 500 --start 20001 --assert-target
npm run test:game
npm run release:check
```

模拟器按真实规则命令运行 1—6 人对局，自动选牌、移动、采集、捐赠和支付洪水成本，最后走本地 RAG 和终局裁决。固定种子可复现，输出局数、操作数、事件数、捐赠次数和结果。它不是访问真实游戏的作弊入口。

`test:balance` 固定每局 6 人，按初始六人计算生存率和登船率；默认混合两名慷慨捐赠、两名均衡储备、两名谨慎储备的机器人，并随种子轮换座位，不偷看未来牌或骰子。`--policy balanced/cautious/generous` 可做策略敏感性检查。自动测试结果不是任意真人策略或真实模型下的保证。

浏览器测试另有临时 HTTP 服务和存档目录。默认自动回归均不读取实际密钥、不调用真实 M3、不覆盖真实对局；显式 `test:knowledge:live -- --live` 是唯一需要真实密钥的可选联调，不包含在发布检查中。

完整规则、未明确事项的本地约定和后续修改入口见 [README](../README.md)。
