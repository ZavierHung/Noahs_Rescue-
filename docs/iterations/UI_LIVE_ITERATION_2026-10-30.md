## 本次实现

- 全部 27 种卡牌图鉴：2 种手牌、13 种科技、12 种灾难。分类与搜索，悬停／键盘简述、点击大图和完整执行效果；兼容手机、学习版与旧局。保留图片比例。
- 常显方舟当前容量、物资总量、下一席缺口与进度；满员不虚构下一席。四种资源统一用图标呈现。
- 下一次洪水：发生轮次与淹没圈、个人固定与任选支出、储备仓减免、当前库存不足可能产生的伤势；方舟 1/2 木、3/4 金属、5/6 电的实际可扣数量与扣后容量。已发生扣库另列，不重复收取。
- 预报由后端调用同一缴纳规则计算，不消耗随机数、不修改游戏；图鉴不含操作接口。本次没有调整卡效或生存数值。
- 独立真实模拟工具：固定种子完整规则游戏 → M3 模拟全员互评 → 本地学术检索与 M3 初审 → 每位幸存者模拟申辩与 M3 回应 → 终判。预算、超时、失败熔断、断点记录与安全脱敏独立于生产存档。

## 测试与实测状态

界面与规则回归已完成：类型检查、生产构建、206 项后端测试以及 33 项浏览器测试通过。新增预报测试跨 192 种缴纳组合与真实 `floodCost` 对照；图鉴测试覆盖全部图片加载、键盘／手机和只读行为。缺少预报数据时明确显示未知，不误报为洪水结束。真实调用工具另有离线注入传输测试，不把这些伪传输测试冒充 M3 成功。

首局联调批次 `ui-learning-live-20261030`，种子 2001，六人八回合，343 次规则命令、669 条事件，规则结算 6 人存活／3 席。**仅执行 1 次真实 M3 HTTP 请求，返回 200；玩家互评未通过事实／格式校验，完整真实成功局数为 0。**没有用离线裁决补成成功。

供应商报告本次输入 199,058 token、输出 1,364 token。旧版本未保留无效候选原文，无法事后确定具体哪个字段或事件索引不符。后续修复方向是减少模拟学生侧重复上下文、提供真实事件引用索引、增加仅含结构信息的失败诊断；不改上帝的完整人设、事实记录或学术检索，不放宽容量／生存约束。原失败报告保留在本地忽略目录，不覆盖。

第二次独立批次 `ui-learning-live-20261030-v2` 使用同一种子。学生输入压至约 1.75 万字符、70 条去重证据；真实 1 次 HTTP 返回 200，输入 6,326 token／输出 979 token。结构诊断定位到 P1 评价 P3 时引用 `#527`：该事件确为 P2 邀约 P3 的合作，已展示在共享证据索引，却只进入 P2 的个人白名单，因而被脚本错误拒绝。**这是新脚本白名单的缺陷，不能归因为模型编造。**修复改为先形成共享索引，再关联参与双方；引用须全部真实且可见，至少一条涉及被评玩家，不过滤、不改写模型返回值。第一次因为没有诊断，仍不能认定是同一原因。

第三次独立批次 `ui-learning-live-20261030-v3`，真实 1 次 HTTP 返回 200，输入 6,533 token／输出 1,752 token。脚本因第一名评价者提交 5 条评论而拒绝；生产游戏允许评价其他所有玩家，六人局为 1–5 人，脚本的人为 1–2 人限制并不一致。本次修复对齐生产人数范围，继续禁止自评、重复对象、虚构／不可见事件及不涉及被评者的证据。这里只定位到数量问题，校验尚未遍历其余条目，**不能宣称整份模型回答已验证有效**。最新修复只通过离线回归，尚未再次调用真实模型。

## 解释边界

M3 扮演不同学生观点与上帝，规则机器人执行行动；这不是招募真实学生，也不是全部操作由 LLM 决策。同模型多角色可能共享偏见。机械校验能验证事件／文献存在、生存资格和容量，却不能保证论证合理、引用解释正确或教学有效。后续需人工审读反驳如何改变理由，再进行真人六人试玩。

真实报告不含请求提示词、原始供应商响应或 Key；只有模拟对局事实、脱敏输出、来源索引和计数。`.env`、玩家存档和 `test-results/` 均保持 Git 忽略。命令与断点流程见 [快速开始](../QUICK_START.md#真实-m3-模拟主动启用消耗模型额度)。
