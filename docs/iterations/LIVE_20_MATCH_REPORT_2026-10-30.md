# 二十局真实 M3 模拟与教育性审查

日期：2026-10-30。范围为 **20 局六人游戏**，不是 20 批。卡牌图鉴、洪水成本与方舟容量提醒已实现。规则预演覆盖全部二十局，但真实 M3 的全流程完成率明显不足，且已通过的判词仍有事实错误；当前不适合无监督教育使用。

## 当前结果

正式用例为种子 2001–2020。已尝试 **19 局真实模型交互，其中 2 局完整通过、17 局失败**；2020 尚未执行。接口连续返回 HTTP 429，冷却超过六分钟后以尚未执行的 2012 单局检查，仍立即返回 429，且未提供有效的整数秒数重试时间，现已停止付费调用。仅凭该状态不能判断是短期限流还是套餐额度耗尽；需要服务恢复后才能继续。失败不会用离线结果补齐，也不会把通过的阶段算成完整对局。

两局可复核的完整样本为 2008 和 2015，共 12 名玩家、9 名幸存者、6 名登船者。样本过小且存在成功选择偏差，**不能用这两局的 50% 登船率代表二十局**。独立规则基线生存率为 85%，实际二十局 LLM 登船率尚不可得。

本轮已实际发出 **178 次 HTTP**：正式用例 136 次、结构化前测 15 次、原始归档丢失但已记录的前测 27 次。上限仍为 300 次，没有因失败或归档丢失重置预算。可复核归档报告的已知输入量 16,954,521 token、输出量 371,863 token；5 次超时／限流响应未报告用量，不能按零费用处理。历史 27 次的执行记录另汇总输入 2,421,071、输出 39,802 token，但原始归档不可恢复，不能与可复核归档混称。

## 实验范围与请求预算

六人完成八回合规则游戏后，由 MiniMax-M3 生成同伴观察、进行真实本地学术 RAG 初审，再由每位幸存者分别生成申辩、上帝回应，最后终判。行动由规则机器人完成，不是所有移动／出牌都交给 LLM，也不是人类学生实验。

正式样本为种子 2001–2020，`mixed / balanced / cautious / generous` 每四局循环，三类完整上帝人设按种子分配。分组只方便断点与最多两组并行，不改变单局规则、策略或人设。运行中不调整数值、知识库、人设或已生成判词。早期 JSON 格式失败后，输出协议单独迭代为结构化工具提交；不同协议分开报告，不冒充同一冻结实验。

| --- | ---: | ---: | --- |
| 前置联调，2001 | 3 | 0 | 脚本误设申辩引用上限，已修复 |
| 原 JSON 第 1 组，2001–2003 | 3 | 0 | 两次引用超限、一次 JSON 错误；连续三局失败停止，2004 未执行 |

上述为早期前测，共 **27 次请求**，不是当前总量。此前另一次对话中的三次联调单列在 [UI 迭代报告](UI_LIVE_ITERATION_2026-10-30.md)。原 JSON 协议单阶段一次请求；新协议每阶段最多两次，每局最多两次格式纠正，所有第一次失败保留计数。认证、HTTP、超时、截断不自动付费重试；连续三局失败停止。不得因不满意模型观点而重抽，不用离线回退补成功。

纯规则预演显示二十局共有 102 名幸存者，全部阶段一次成功需要 264 次 HTTP（每局 3 次固定请求，加每名幸存者 2 次）。这是理想请求规划，不是已完成数量。历史 2007 的原始归档后来丢失，不纳入现有可复核成功数；后续同种子的模型调用作为独立样本保留失败。各运行均有预算，跨运行合计仍受 300 次限制。完整上帝上下文较大，HTTP 上限不是费用保证。

### 结构化协议迭代

新协议使用同一 MiniMax-M3 和完整人设，通过单一指定工具提交互评、申辩和裁决数据；不是允许模型调用任意外部工具。生产中的生存资格、容量、真实行为引用、三领域学术引用校验均保留。只把受控错误类别反馈给模型重新生成一次，不截掉多余证据、不本地修饰结论。默认正式游戏适配器仍保持兼容，实验显式开启新协议。策略偏移参数确保拆组后种子 2008 仍用原 generous 策略。

3000 token 神判输出上限的首批结构化实验结果：种子 2001/2002/2003/2005/2006 的互评均通过，但初审均未完成生产校验，共 15 次 HTTP，完整成功 0。五次初审均用满一次有记录的格式修复；十个神判响应的输出量都达到 3000，其中一次明确返回 `max_tokens`。其他响应的 `tool_use` 只表示供应商宣告提交工具，不能证明对象满足字段与引用约束。错误涉及学术引用、裁决结构、证据及容量；未放宽任何校验。

该阶段结束时，本轮累计 **42 次 HTTP**，余量 **258 次**。下一协议版本仅增加显式、可冻结的神判输出上限参数，尝试 6000；默认生产值仍为 3000。输出预算紧张有观测证据，但不能认定它解释所有失败。不恢复旧协议报告，不修改已失败候选，不用满意的判词覆盖失败记录。

### 测试输出隔离事故及修复

执行浏览器回归时，Playwright 默认清理了共用的 `test-results/`，意外移除了早期原 JSON 实验（包含 seed 2007）及上一轮联调的本地原始 JSON；结构化 s1 的第一局事件文件也受影响。正在内存运行的 s1 报告随后正常重新落盘，s2 在清理后创建。正式玩家存档与环境密钥不受影响。

此前已核对的请求次数、token 汇总、判词问题保留在本报告和执行记录中，但不能据此伪造或还原原始模型输出。因此 seed 2007 只作为“已观察到全流程成功、原始归档丢失”的历史结果，不能冒充当前可复核的完整归档。旧 27 次请求仍计入预算，绝不因文件丢失重新置零。后续若重跑同一规则种子，必须是新的模型样本。

已将 Playwright `outputDir` 独立为 `test-results/browser/`，增加路径隔离测试，避免浏览器自动清理同级付费模拟记录。该测试通过；没有通过再次清理父目录来验证。

## 确认后的首个联调

早期记录原路径：`test-results/learning-live-confirmed-20-20261030/report.json`，已在上述事故中丢失。种子 2001 的真实互评与上帝初审通过；P1 申辩给了 7 条引用，测试脚本的人为上限 5 造成拒绝。生产接口只约束最终申辩文本不超过 4000 字，不限制引用条数。由于数量检查在前且无效候选未保存，不能认定这 7 条引用已全部核验有效。

三次调用分别报告输入 token 6,560／206,080／4,898，输出 908／1,709／293，合计输入 217,538、输出 2,910；缓存读取另报 384。互评、初审均为真实请求，但此局未完成全员交互与终判，完整成功局仍为 0。

针对脚本与生产接口差异，一次核对申辩长度与引用、已在裁决中出现的真实事件可见性，以及互评评分／评论的可选性。修复保留真实性、唯一性、可见性和至少一条涉及被评／发言者的证据约束，不删减模型返回来凑通过，不改旧失败报告。修复完成后使用新记录执行正式样本。

对齐修复的 21 项离线测试全部通过，随后冻结脚本。正式组 1 的种子 2001 在互评阶段失败：P6 对 P1 给了 4 条引用，超过生产接口最多 3 条的真实限制。此次与先前脚本误拒不同，应记作模型输出不符合游戏接口；不放宽规则、不裁掉第 4 条、不把离线裁决补成成功。继续预定种子，统计真实失败分布，不重抽同局直到得到满意回答。

## 首个初判的语义抽查

初判确实引用了库内 CORE、IPCC 与 Ostrom 的材料，说明论文不是登船分配公式，捐赠累计和三席容量吻合。但“引用存在”不等于表述准确：

- IPCC 应用称 P3/P5/P6 的伤势 5／4／3“均已达到耐受值”。事件 #664／#666／#667 的耐受值均为 5，只有 P3 达到上限；更准确的表达是均在耐受范围内。
- P6 对 P1 的互评把 #604 说成 P1 接受 P6 邀约。实际发起人 P1、受邀人 P6；双方合作与获益真实，但方向错误。
- P5 初判“两次科技均有代价”有歧义。真实科技事件共四次 #143／#475／#558／#645，应区分总次数与讨论中的有代价子集。

以上保留的是事故前审读记录，原始判词已丢失；未在实验中途修改判词。后续重点是帮助模型准确读取合作双方、比较伤势与耐受值、区分科技总次数与子集。学术文本具有讨论价值，但上述样本不足以证明学习增益或可靠的教育解释。

## 首个完整对局：2007

历史观察中，真实 15 次请求覆盖互评、初审、六名幸存者申辩及六次上帝回应、终判。六人存活、容量两席，初判 P1/P6，讨论后终判 P4/P6。原路径 `test-results/learning20-20261030-g2/` 已丢失，以下为事故前审读记录，不算当前可复核的完整样本。

独立语义抽查发现：全部上帝引用编号存在、十个不同文献 ID 均在库内，判词有外部成本、共同治理、公平及文献局限的实质讨论。但仍有重要错误：

- P1 讨论阶段叙述暂列 P1/P6，结构化名单却只有 P1；下一阶段恢复两人。显示名单必须以经过校验的 decisions 为准。
- 终判说 P1 与 P4 捐赠持平，实际 12 对 11；说 P1 个人环境影响比 P6 更差，实际均为 −1。
- 把储备仓事件 #580 的“环境 6→5”读成行动前已为 5。
- P3 的时序被简化为科技后修复，遗漏“扩张→公共修复→再次无人机损耗”的最后一步。
- 能正确纠正 P4 洪水次数，却也出现多余纠错、遗漏早期公共治理的情况。知识引用准确存在，不代表因果解释全部可靠。

这一局只能确认完整交互与容量控制，不能单独验证死亡玩家排除，也不能证明学生学习效果。后续优化应优先考虑统一名单渲染、确定性的数值比较表、行动前后状态和公共／个人影响分列、明确纠错记录。

## 结果记录原则

最终分别统计预定 20 局、尝试数、完整真实成功数、失败阶段、实际请求与 token 用量；不只展示成功子集。生存由规则决定，登船由真实终判决定；未终判的对局不能填入登船率。人工语义审查单独列出样本和事实核对，不把结构通过率冒充知识理解准确率。

Key、请求提示词和原始供应商响应不进入报告；本地 JSON 仅保存模拟事实、脱敏输出及计数，位于 Git 忽略的 `test-results/`。不读写真实玩家存档、不修改主分支。

## 独立规则基线（不含 LLM）

这部分使用相同二十个种子，不能当作真实终判或人类学习效果。

| 策略 | 对局 | 生存人数／玩家数 | 生存率 | 席位／玩家数 |
| --- | ---: | ---: | ---: | ---: |
| mixed | 5 | 24/30 | 80% | 15/30 |
| balanced | 5 | 30/30 | 100% | 13/30 |
| cautious | 5 | 27/30 | 90% | 10/30 |
| generous | 5 | 21/30 | 70% | 23/30 |

席位占比 50.83%，但逐局取 `min(席位,幸存人数)` 后最多 57 人可登船，即 47.5%。慷慨策略存在四个空席无法由死亡玩家使用，体现贡献与自救的权衡。每组只有五局且种子不同，不能当成随机对照证明策略因果。

## 6000 输出上限的早期语义审查

长答版本 `t6000-a/b` 已结束：2001 在 P6 申辩截断，2002 在 P2 讨论超时，2003 在最后一名幸存者的讨论截断，2005 在终判引用校验失败，2006 在 P4 讨论引用校验失败。五局共 55 次 HTTP，47 个阶段通过，但完整成功为 0；2004 当时因三连失败熔断未开始，后在独立简明版本执行。该阶段累计 97 次请求，不因失败或原档丢失重置预算。

对输出长度的只读核查显示，一些讨论正文已有 1500–2300 字，还同时重复六份个人理由及四至六篇文献应用，越往后越长。后续未执行种子显式启用 `--concise`，建议短正文、短理由、初终三领域各一篇／讨论两篇、聚焦少量真实事件；完整输入和原校验不变，超过建议长度的合法回答仍接受。补充伤势、公共机会和前后状态的通用解释提示，绝不指定该让谁登船。不同输出协议分开报告，不把中途工程改进说成同一冻结条件的随机对照。

seed 2001 初审与前两次讨论的独立抽查（不是完整终判结论）：

- 上帝把 #662 的 P1 `remainingInjury=0` 读成耐受余量为 0，并用作不利理由。实际 `tolerance=5`，耐受余量为 5；P3 #664 才达到上限。
- 对 P5 的决定称未参与公共事件，却在同阶段 learning 中承认 #412 的方舟蓄电决策，内部不一致。
- 讨论文字称保留 P6 船位，但 `decisions` 给出 `board:false`。界面名单应以校验后的布尔结果为准，不能假设叙述一致。
- 对 P3 洪水付款、P6 名刀逃生存在事件归属误读；互评仍有邀约发起／接受方向混淆。
- 用 P2“没有公共决策”作负面归因，但本局系统只把决策权限分配给 P3/P4/P5（#83/#224/#410）。没有获得机会不能解释成不愿承担责任。
- 正面例子：上帝能核对完整捐赠记录，纠正学生只看局部笔记的推算；P2 申辩也促使其撤回先前分类。互动确实影响解释，但准确性不稳定。

下一版应先增加确定性的“剩余伤势／耐受上限／计算余量”、公共决策“获分派／已执行”、明确事件参与双方及数值比较表，避免把模型心算、漏读和机会差异变成道德结论。保留全部原始日志和完整人设，不用这些摘要替换事实。现在不能将格式成功表述为适合无监督教育使用。

## 数值与机器人偏差的独立诊断

只读离线审查，不计入真实二十局，也不改变本批冻结规则：当前二十局科技请求环境净变化 −129、无人机增产 −25、高经济／高社会灾难入场 −40、公共事件 +21；触底截断后实际合计 −134。互助信标 38 次、共享补给舱 32 次是最大的两个负代价来源。机器人不使用信标主动交换，却仍会部署并支付成本；435 次科技抽取仅放弃 6 次，包含 28 次无新增被动收益的重复部署。

## 本次工程迭代与后续重点

已实现：全卡牌只读预览与航程提醒；真实模型独立测试入口；结构化输出与严格原规则校验；有限格式修复和逐次请求／已知用量计数；可冻结的输出上限及简明表达选项；断点防混用；浏览器与付费实验归档隔离；只读汇总工具。最后补上首次 HTTP 429 即停止批次的保护，重启同一已熔断批次不会再发请求。仅保留 0–86400 的整数 `Retry-After` 秒数，不保存任意响应头／错误正文，不自动等待重试。没有修改卡效或抹掉失败判词。

后续优先修复的是事实可靠性，而非继续扩大模型预算：增加由代码计算的行动次数、邀约双方、环境前后值、伤势／耐受余量和公共决策机会表，并保留原始事件供核验；将玩家申辩与已验证事实分开；对反驳前后的事实纠正单独留档。还需针对长答截断设计更小的单阶段输出合同，但不能直接删减完整上帝人设或事实输入。上述改造尚未实现，不能当作本次成果。

重新完成稳定的模型闭环后，再用真实六人试玩观察理解、争论质量和乐趣。机器人策略诊断仅提示生态成本与生存取舍，暂不据此同时改动多张卡牌，以免失去可比较的规则基线。
