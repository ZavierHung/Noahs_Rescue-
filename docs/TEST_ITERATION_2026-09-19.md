## 本轮范围

在已有微信小程序和六人浏览器模拟器上做回归及边界测试。保留上帝核心流程、完整数据后端人设、RAG 和人工确认奖惩，不改变数值玩法，不部署，不提交真实玩家存档或密钥。

## 从测试中发现的问题

原有 34 项测试全部通过，但新增的首批 5 个边界用例全部失败。这说明原测试覆盖了正常流程，却未覆盖异步请求到达顺序和页面切换。本轮先保留失败用例，再修改共享控制器，使问题可以持续回归。

| 问题 | 本轮修复 |
| --- | --- |
| 慢轮询在开局请求之后返回，把界面从游戏退回等待室 | 每次操作记录序号；过时轮询被丢弃，并按房间 revision 防止状态倒退 |
| 首次断网后，连接恢复但角色资料一直空白 | 轮询会重新补齐缺失角色资料；连接错误与业务错误分开处理 |
| 旧页面关闭后，尚未结束的初始化仍覆写新页面身份 | 已卸载控制器停止发布状态、写入本地身份及继续轮询 |
| 建房或准备请求失败，一键模拟仍可能显示成功 | create/join 返回实际房间；六人助手逐步核实建房、加入、准备及最终状态 |
| 原生 setData 可能收到 undefined 成员；界面数据带内部本地凭证 | 缺失成员统一为 null；内部凭证与角色房间映射不进入视图数据 |
| 等待操作时查看历史，后台操作结束强行跳走 | 导航也有独立序号，后台结果只更新数据，不抢占当前页面 |
| 切换角色/房间后保留旧分数编辑和旧汇报 | 清理跨身份、跨房间表单；神谕锁定或游戏结束时清理未提交分数编辑 |
| 六人同屏里一位玩家打开长历史记录，其他同排手机被垂直居中推到下方 | 去掉网格手机的自动垂直边距，增加同排顶部对齐断言 |

## 测试分层

### 规则、接口和共享客户端

`npm test` 在隔离临时目录运行。新增异步乱序、恢复连接、旧页面销毁、六人助手部分失败、原生表单上下文切换等回归用例。保留原来的角色冲突、开局门槛、分数边界、神谕重复触发、跨房间并发、确认结算幂等、退出重连、存档恢复及完整六人 HTTP 流程测试。

### 真实浏览器自动化

新增 `tests/browser/` 与 `npm run test:e2e`：使用真实 Chrome/Chromium 页面点击、键盘滑条、文本输入、弹窗确认、刷新以及手机视口检查。通过请求转发把页面连接到独立临时 HTTP API；这个 API 使用实际房间服务、Agent Loop、RAG 与 JSON 存储，但不创建 LLM 适配器，也不读取 `.env`。

这与只验证接口不同：页面的按钮、表单、导航、跨玩家同步和浏览器运行时错误都会参与断言。测试结束关闭浏览器页面和测试服务，只清理该测试创建的临时目录。

测试截图和失败轨迹写入 `test-results/`，HTML 报告写入 `playwright-report/`，两者都被 Git 忽略。Playwright 的安装与运行方式参考[官方文档](https://playwright.dev/docs/intro)。

浏览器场景：六人建房/准备/开局、键盘调整滑条、灾难反馈、RAG 展开、跨阵营汇报与驳斥、确认前后分数比较、二次触发、未完成任务、退出重连、结束、历史详情、刷新恢复；另测 390px 手机视口无横向溢出、人数不足禁止开局、部分准备失败、角色接口断网后自动恢复。截图检查发现的同排布局问题已修复并纳入断言。

## 运行方法

```bash
npm ci                    # 根目录浏览器测试依赖
npm --prefix app ci       # 前端依赖
npm run check             # Node 测试 + 类型检查 + Web 构建
npm run test:e2e           # 真实浏览器操作测试
npm run check:all          # 以上两组一起执行
```

浏览器测试默认复用已有 `http://localhost:3000/mobile` 页面服务；未运行时自动启动前端。API 始终独立，不复用用户的 8787 服务。macOS 有 Chrome 时直接使用隔离的 Chrome 测试实例；其他环境可先执行 `npx playwright install chromium`。不使用用户日常浏览器的个人资料和登录状态。
