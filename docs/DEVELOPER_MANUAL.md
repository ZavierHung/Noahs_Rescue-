# 诺亚救援开发者手册

适用版本：网页版 `0.4.1-local`，核对日期：2026-11-02。面向接手开发、测试、调数值和维护内容的开发者。本文以当前代码和数据配置为准；新网页对局默认采用学习 v2，旧存档保留其模式差异。

游戏把洪水生存、公共物资建设与有限席位分配分开处理。规则引擎决定物资、伤势、生存和容量；上帝读取行为证据、人格与学术材料，经过申辩后决定登船名单。上帝不能复活玩家、增加席位或施加灾难奖惩。

玩家入门见 [玩家手册](PLAYER_MANUAL.md)，学术来源见 [学术知识库报告](ACADEMIC_KNOWLEDGE_REPORT.md)，历次试验见 [学生视角迭代报告](STUDENT_ITERATION_REPORT.md)。

## 二 开发环境与启动

使用 Node.js 22.13 及以上；前端为 React 19、TypeScript、Vinext/Vite，后端为 Node.js 原生 HTTP 和 ESM，存储为本地 JSON。测试采用 Node 内置测试运行器和 Playwright。

在仓库根目录执行：

```bash
npm ci
npm --prefix app ci
npm run dev:mock
```

打开 `http://localhost:3000/`，API 默认 `http://localhost:8787`。`dev:mock` 强制离线裁决，不发送模型请求。若端口已有服务，先确认并复用或正常停止，避免重复启动。

需要真实模型时，在本机创建 `.env`，参考 [.env.example](../.env.example)，然后运行 `npm run dev`。不要覆盖已有密钥配置；配置变更后重启 API。

| 配置                              | 用途                                                                               |
| --------------------------------- | ---------------------------------------------------------------------------------- |
| `GAME_LLM_MODE=mock`              | 强制离线；`auto` 根据密钥配置启用模型                                              |
| `MINIMAX_API_KEY`                 | 仅服务端读取；模板留空，实际值不进 Git                                             |
| `MINIMAX_BASE_URL`                | 当前适配器默认 `https://api.minimaxi.com/anthropic`                                |
| `MINIMAX_MODEL`                   | 当前默认 `MiniMax-M3`；旧标签 `MiniMax-M3.0` 归一为同一模型 ID                     |
| `MINIMAX_TIMEOUT_MS`              | 当前默认 60000 毫秒                                                                |
| `GAME_API_HOST` / `GAME_API_PORT` | 默认 `127.0.0.1` / `8787`                                                          |
| `NEXT_PUBLIC_GAME_API_URL`        | 前端 API 地址，不是密钥配置位置                                                    |
| `GAME_DATA_DIR`                   | 可替换运行数据目录；启动还需要该目录内的人格文件和实验台知识配置，不能只指向空目录 |

代理启动可用 `npm run dev:proxy`，继承已有 HTTP(S) 代理或 macOS 手动代理，不修改系统设置；所用 Node 需支持 `--use-env-proxy`。常规离线测试无需代理和 API key。

### 主要状态

| 字段                            | 含义                                                                      |
| ------------------------------- | ------------------------------------------------------------------------- |
| `status`                        | `playing` → `awaiting_judgment` → `review` → `finished`                   |
| `round` / `turn` / `phase`      | 全局轮次、轮内座位与当前步骤                                              |
| `players`                       | 每人位置、库存、手牌实例 UID、装备、捐赠、伤势、世界影响及本轮标记        |
| `pending`                       | 当前必须处理的选择及 `actor`，可保存被打断的阶段/选择                     |
| `world.base` / `attributes`     | 基础分数 / 叠加持续修正后的生效分数；不保存个人三属性                     |
| `ark` / `donations`             | 实际方舟库存 / 历史捐赠；洪水减库不抹除贡献记录                           |
| `events`                        | 当前有效历史分支的因果事件，供上帝引用                                    |
| `revision`                      | 每次成功修改递增；撤回也递增，不倒退版本号                                |
| `rules` / `publicEvents`        | 本局数值快照 / 事件规则快照及独立随机状态                                 |
| `peerReview` / `judgment`       | 同伴观察 / 冻结证据、各阶段裁决、发言与引用                               |

随机状态在后端保存，GET 不抽牌、投骰、发奖或写入迁移。前端查看他人、悬停、预览与洪水预测都不改变对局。

## 四 完整游戏流程

```text
选角色与出生旗 → 创建局与规则快照 → 发首轮手牌
  → 每轮开始抽牌及必要的公共事件
  → 每名玩家：用牌 → 移动 → 采集 → 上交
       ↳ 卡牌/灾难选择：暂停当前步骤 → 指定玩家响应 → 恢复
  → 全员结束：轮末灾难 → 第3/5/7轮洪水 → 下一轮
  → 第8轮末：最后撤离 → 种子救生 → 确定生存与容量
  → 全员互评或跳过 → 上帝初判 → 幸存者逐人发言或放弃
  → 最终登船名单 + 分层学习结果 + 日志留档
```

开局个人四种资源和方舟库存均为 0，世界三属性均为 10；每人抽 1 张行动卡。一个“回合/轮”包含所有玩家的一次行动，不是单人点一次按钮。

| 轮次 | 开始抽牌                    | 轮末                                            |
| ---- | --------------------------- | ----------------------------------------------- |
| 1    | 每人 1 张                   | 下一轮                                          |
| 2    | 每人 1 张；学习 v2 公共事件 | 下一轮                                          |
| 3    | 不抽                        | 轮末灾难、第一次洪水、名刀响应，之后每人抽 1 张 |
| 4    | 不抽；学习 v2 公共事件      | 下一轮                                          |
| 5    | 每人 1 张                   | 轮末灾难、第二次洪水、名刀响应                  |
| 6    | 每人 1 张；学习 v2 公共事件 | 下一轮                                          |
| 7    | 每人 1 张                   | 轮末灾难、第三次洪水、名刀响应                  |
| 8    | 每人 1 张                   | 轮末灾难、撤离、生存结算、审议                  |

普通步骤 `cards → move → gather → donate` 都可以跳过。出牌并非每人仅限一张；在允许阶段可以继续使用持有的牌，直到主动推进步骤。每人常规移动、采集和上交步骤各一次。邀约/信标也可在没有待决选择的常规移动、采集、上交步骤发起，不额外消耗这些步骤。

基础移动最多 2 格，沿相邻陆地；可以不移动。淹没区滞留者允许沿合法向内路线逃生，安全位置不能主动进入淹没区。采集只发生在当前位置未淹没、有资源且未被灾难限制的格子，每次基础 1 份。常规采集不是先来者拿走后全场永久无货；生态崩坏另有共享历史限制。

上交可在任何位置进行，将个人选定库存转入方舟，结束自己的回合行动。不能透支、产生负数或从方舟拿回物资；纠错使用撤回。

### 行动者与打断恢复

普通行动者为当前座位；有 `pending.actor` 时，以指定响应者为准。例如 P1 发邀约后由 P2 接受，不允许 P1 替代。UI 只读视角不改变行动者。这里是本机规则控制，不是经过认证的远程账户权限。

科技行动可打断普通行动、普通卡牌选择或洪水响应；不能打断灾难资源选择、生态阻止、公共事件、终局撤离或审议。被打断的选择保存并在完成后恢复，嵌套选择必须保持原拥有者、队列和阶段。

## 五 全部行动卡与科技逻辑

### 抽牌与公共约定

行动池只有邀约和科技，每次各 50%，有放回。科技池 13 种，每次独立等概率抽 2 张再选 1，允许抽到相同牌；不是预先洗好的有限牌堆。科技被选中后立即执行或部署，不另放入科技手牌。

普通手牌上限 5；自然抽牌满手时，新牌进入行动弃牌堆。原型机与蓝图主动领取满手时必须先弃一张。6 种装备型科技同名不叠加，重复选择不重发世界增减；放弃科技选择也不退回已消耗的科技行动卡。

下表“世界变化”为首次成功执行的请求增量，顺序为经济/环境/社会，`—` 为 0。实际值受 1—19 截断、持续修正和后续灾难连锁影响，事件分别记录请求与实际变化。它们是共同世界变化，不是个人得分。

### 两种行动卡

| 名称与 ID         | 条件与完整流程                                                                                                                                                                                                                                                                                |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 邀约 `invitation` | 选距自己地图直线距离最近的两名其他玩家之一，同距按座位；不足两人取全部，单人无法邀约。发起者先选想要的资源，对方接受时独立选一种，双方各新增 1 份，可不同种、无需原库存。接受才消耗卡；拒绝不消耗、不发资源，可重试。接受时重新验证距离、牌和炼金限制。不是交换，不受社会失序的远程交易限制。 |
| 科技 `technology` | 消耗行动卡进弃牌堆，展示 2 张科技，选 1 执行。需要成本/目标的牌先填写；无法执行可选另一张或放弃。装备保存至玩家 `equipment`，即时牌结算后不成为装备。                                                                                                                                         |

## 六 全部灾难逻辑

### 触发和结算顺序

| 生效分数 | 经济                    | 环境                    | 社会                        |
| -------- | ----------------------- | ----------------------- | --------------------------- |
| 1—2      | 经济萧条 + 通货紧缩     | 生态崩坏 + 稳态失衡     | 社会失序 + 阶层固化         |
| 3—6      | 经济萧条                | 生态崩坏                | 社会失序                    |
| 7—13     | 无                      | 无                      | 无                          |
| 14—17    | 先发展再治理            | 资源保护                | 全民保障压力                |
| 18—19    | 先发展再治理 + 财富悬殊 | 资源保护 + 生态管制冲突 | 全民保障压力 + 强制互助制度 |

高位不等于纯奖励。每张卡按 ID 比较进入/离场：18→19 不重复发奖；18→17 仅解除极端卡；离开阈值后重入才重新执行进入效果。每波先快照所有新卡，再按普通档到极端档、档内经济到环境到社会执行；分数变化继续检查连锁。已产生的选择队列不会因为卡随后离场而丢失。

| 灾难与 ID                       | 时机与具体实现                                                                                                                                                                                                                              |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 经济萧条 `depression`           | 进入经济低位时收回已装备且原卡 `status.economy > 0` 的科技，即空间戒指、名刀、采矿无人机、互助信标。不撤销历史收益，不持续禁止再次获得这些装备。                                                                                            |
| 通货紧缩 `deflation`            | 进入极低经济时，每人手中移除一张科技行动卡，无牌则不扣装备；在场手牌上限 −1。已有超限牌不额外强弃，后续抽牌/回收使用新上限。                                                                                                                |
| 先发展再治理 `develop-first`    | 进入经济高位时环境 −1，每人依次从四类资源自选 1 份新增。                                                                                                                                                                                    |
| 财富悬殊 `wealth-gap`           | 进入极高经济时社会 −1；排队轮到本效果时按现存库存排名，最穷向最富转移 1 金属。“晶矿”映射为金属；没有金属记实际 0，不改扣别物。                                                                                                              |
| 生态崩坏 `eco-collapse`         | 学习局在场时全体共享资源格采集历史：第 r 轮采过，第 r 与 r+1 轮不能再采，第 r+2 轮恢复。覆盖四种资源格，离场解除限制但保留历史。这是游戏休养抽象，不代表金属或电力自然再生。                                                                |
| 稳态失衡 `steady-imbalance`     | 进入极低环境时每人自选失去 1 资源，无库存自动跳过；随后每人随机六方向移动 1 格，非法方向原地，不重抽。之后每轮末一次；进入当轮已漂移，轮末不重复。                                                                                          |
| 资源保护 `resource-protection`  | 环境高位在场时，当前玩家选资源格并写原因，确认“保护成功”使环境 +1，或“开发受限”使经济 −1。是人工条件确认，不由采集/捐赠自动推断，也不同时执行两种结果。                                                                                     |
| 生态管制冲突 `eco-conflict`     | 环境极高时社会持续修正 −1，离场解除，不逐动作重复扣。选中会降低环境的新科技，在执行前让同格/相邻且有资源的玩家按座位回应；一人支付 1 资源即取消该科技收益和世界变化，已用科技行动卡不退。全员放行才执行。当前不拦公共事件或无人机采集增产。 |
| 社会失序 `social-disorder`      | 在场限制远程交易/争夺；当前信标和机械爪本来就要求相邻，因此不会再缩范围。新版邀约公共领取、补给舱与捐赠不受阻。旧存档的未完成交易仍按原协议并重新检查位置。                                                                                 |
| 阶层固化 `class-lock`           | 每次采集前按个人现存库存排序，前 `floor(人数/2)` 为富者，掷一次 50% 判定：富者可能 +1，其余可能 −1；另一半概率不变。与基础/无人机合算，最低 0。排名、随机值与实际产量均留档。                                                               |
| 全民保障压力 `welfare-pressure` | 进入社会高位时环境 −1，每人依次自选 1 份现有四类资源，作为新增保障物资。                                                                                                                                                                    |
| 强制互助制度 `mutual-aid`       | 进入极高社会时经济 −1；每轮全员结束、洪水前，最富自选 1 份库存转给最穷。一轮一次；单人或全员零资源无转移。                                                                                                                                  |

排名只算个人现存四类库存，不算方舟和捐赠。同分按座位：最富取靠前，最穷取靠后。轮末先互助、后稳态漂移、再洪水。生态管制的持续修正在 `world.modifiers`；UI 主数字与阈值用 `attributes`，主持人滑条提交 `world.base`。

## 七 洪水 生存与方舟容量

### 洪水追踪卡

| 轮末 | 淹没范围                    | 方舟支出          | 每人支出                         |
| ---- | --------------------------- | ----------------- | -------------------------------- |
| 3    | Zone 3 外环                 | 骰定一种资源 1 份 | 木头或金属 1 份                  |
| 5    | Zone 2 中环，外环继续淹没   | 骰定一种资源 2 份 | 种子 1 + 木头/金属/电力任选 1    |
| 7    | Zone 1 内环，中外环继续淹没 | 骰定一种资源 3 份 | 电力 1 + 种子 1 + 四种资源任意 1 |

每次洪水开始只投一次六面骰，1/2 扣木头、3/4 扣金属、5/6 扣电力。同一种物资不足按余额扣，不改扣其它种、不重掷；不会每位玩家确认都再次扣方舟。个人先算固定成本及储备仓减免，再从剩余库存选择任选项。第三次任选仍可选种子或电力，只要固定支出后有剩余。

个人减免后每欠缴 1 份积累 1 伤势，不立刻淘汰。第 8 轮末给仍在淹没区者一次最多 1 格合法向内撤离；不能再使用牌、采集或捐赠。随后个人种子自动每份恢复 1 伤势，至归零为止，实际消耗留档。最终安全位置且剩余伤势不超过 5 才生存，留在淹没区即不具登船资格。

当前容量公式：

```text
物资份数 = 方舟木头 + 金属 + 电力 + 种子
载客量 = min(初始玩家数, 6, floor(物资份数 / 17))
```

四类均计数，不要求固定材料比例；容量可为 0。17/34/51 份分别提供 1/2/3 席，最高不超过玩家数。到下一席通常还需 `17 - (份数 % 17)`，已满最大容量时 UI 显示封顶。洪水可让容量下降；登船不再扣一遍库存。预测只显示骰子可能造成的损失区间，不能保证下一次具体损失。

### 玩家互评

生存结算后、初判前，所有玩家依次提交或明确跳过，包括未存活者。可评价部分同伴，不可自评或重复评价同一人。每条可给 1—5 整数评分或不评分，评论最多 600 字，至少有评分或评论；最多附 3 条真实行为事件，不能用他人评价或上帝意见冒充行为。

评分不求均分、不兑换船位；跳过不扣分。首次成功提交或跳过后锁定游戏撤回，避免评价发生后改写依据。相同内容可安全重试，不能覆盖已提交评价。评论只是待核实意见，初审/终判检索话题每位最多 180 字、总计最多 1080 字，评分不用于检索。

## 九 上帝 Agent Loop 与学术知识

### 输入和处理阶段

1. 规则完成最终生存结算；全员互评完成后才允许 `judge`。
2. 初判构造冻结的 `context`：最终世界/灾难、所有玩家库存装备和生存、方舟容量、捐赠、全局事件、机会背景、互评、学习结果及职责约束。`context.facts` 将同一批事件按玩家归纳，不是第二套评分或新事实。
3. 初判随机选一位上帝：增长与突破之神 `radical`、平衡与共存之神 `balanced`、秩序与守护之神 `conservative`。同局后续沿用同一身份。
4. 每阶段从数据后端读取完整人格与职责，重新检索学术证据。讨论优先当前申辩；初判/终判可用有限互评话题和此前陈述。
5. 调用模型或离线裁决，验证玩家覆盖、幸存资格、席位上限、真实事件与文献引用；失败回退并标记，不接受模型修改游戏状态。
6. 初判生成暂定名单及每位幸存者的问题。幸存者按座位各一次发言（最多 4000 字）或明确放弃，每次再检索、回应与复核暂定名单。
7. 全员回应后 `finalize` 才生成最终名单。零幸存者无需虚构讨论，仍可完成终判。各阶段内容保存到本地审判记录。

这是跨 HTTP 请求持久化的有界阶段循环，不是无期限自主 Agent。玩家必须推进交互；刷新可继续，普通游戏中没有任意提前审判按钮。

### 哪些 Prompt 给模型

| 来源                                                                         | 进入位置与职责                                                                                                                         |
| ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `server/data/gods.json` 和 `god-prompts/{radical,balanced,conservative}.txt` | System 中的完整人设；不以一句风格摘要替代                                                                                              |
| `server/data/prompts/boarding-role.txt`                                      | System 追加当前登船职责和阶段约束，覆盖原设计里的旧奖惩职责                                                                            |
| `server/data/prompts/academic-reading.txt`                                   | System 追加学术应用、三领域、证据与适用局限要求                                                                                        |
| `server/src/llm/minimax.js`                                                  | 基础结构输出与数据边界；User 中发送 `stage`、`playerId`、`context`、`evidence`、`conversations`、`rebuttal`、`previous` 和输出结构要求 |

模型需对每名玩家给 `board`、理由和真实 `evidence` 事件序号。学术 `learning[]` 在初判/终判至少引用 3 篇不同材料并覆盖经济、环境、社会；讨论至少 2 篇。只能引用本次 RAG 返回的 `sourceId`，解释具体行为和局限。每名玩家的决定至少包含一条非意见行为事件。

人格和职责文件每次模型阶段重新读取；**只改 `god.md` 不会同步生效**。按照当前设计，审判不保存 Prompt 原文、路径或哈希。更改人格文件会影响进行中审议的下一阶段，但保留已生成的历史回应；因此内容变更应在 Git 中说明。

### RAG 的实际能力

学术库在 `server/data/academic/library.json`，当前为 `academic-zh-v2.0`，22 个独立来源：经济 7、环境 7、社会 8；其中 11 本教材、1 份课程指南，另 10 份研究/报告等材料。中文内容是概念说明与有限转述，不是全文翻译或原文全文向量库。原件链接与适用局限独立保存。

检索在本地运行：中英文术语映射、中文关键词相关性、Hash-256 弱辅助嵌入，再考虑人设视角、领域、教材与研究覆盖；通常返回最多 6 条。这不是本地生成式大模型或生产级语义理解模型。人设不能强塞无关资料，也不意味着作者本人属于某种政治立场。扩库和检索参数修改后重启 API。

每阶段 `judgment.history[].rag` 保存查询、关注点、文献证据、库版本和库哈希；与不保存 Prompt 快照是两件事。`judgment.context` 保存冻结游戏证据；`conversations` 保存玩家原话、放弃标记、回应和模型/回退标记；`history` 保存逐阶段名单与引用。

离线裁决按“捐赠份数×3 + 合作次数×2 − 争夺次数×2 + 对上帝关注领域的个人累计世界影响”排序，再排除未存活者并按容量截取，同分按座位。激进关注经济、中立关注社会、保守关注环境。合作包括成功邀约与信标交换；不根据自由陈述或人气打分。界面明确显示离线回退，不能把它称为理解了玩家的申辩。

真实模型即使通过引用结构校验，仍可能误认行为主体、数量或因果。已知限制见 [真实 M3 测试报告](iterations/LIVE_20_MATCH_REPORT_2026-10-30.md)：此前 20 局目标并未全部完成，不应把规则机器人批次写成真实 AI 的完整二十局验证。

创建 API 不默认开启学习模式，非网页调用者须显式传 `learningMode: true`。不要手动指定固定船位；当前容量由物资计算，遗留 `seats` 参数不用于赋予席位。

行动公共字段为 `{ type, actor, revision, ... }`。回合动作/选择的 `actor` 取当前 GET 的 `activePlayerId`，不能取 UI 正在查看的玩家。过期版本返回 409，非法参数/阶段一般返回 400，不存在对局返回 404。收到失败后刷新权威状态，不在前端“补扣”资源。

| `type`                             | 主要附加参数                                                                                                                                   |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `play`                             | `cardUid`；邀约另加 `targetId, resource`；科技进入两选一                                                                                       |
| `choose`                           | 由待决类型决定：`techId`、`resource`、`cardUid`、`tileId`、`accept`、`block`、`optionId` 或 `decline`；炼金另有 `spend`，机械爪另有 `targetId` |
| `beacon`                           | `targetId, give, receive`；两资源包各总计 1，接受方 `choose + accept`                                                                          |
| `discard`                          | `cardUid`，按当前允许阶段弃手牌                                                                                                                |
| `skip`                             | 推进普通步骤，不能跳过必须结算的响应                                                                                                           |
| `move` / `blade_move` / `evacuate` | `tileId`，分别用于常规、名刀、终局撤离                                                                                                         |
| `gather`                           | 学习无人机可加 `boost: true`，默认普通采集                                                                                                     |
| `donate`                           | `amounts` 四资源包，至少 1 份，不能超过个人库存                                                                                                |
| `pay_flood`                        | 需要任选成本时给 `resource`；实际固定/减免由后端计算                                                                                           |
| `set_world`                        | `attributes: {economy, environment, society}, reason`；无待决选择才可执行                                                                      |
| `confirm_protection`               | `outcome: protected/restricted, tileId, reason`                                                                                                |
| `undo` / `redo`                    | 使用修正前的当前行动者和版本，不能用历史操作人代替                                                                                             |
| `peer_review`                      | `entries: [{targetId, rating, comment, evidence}]`，或 `waive: true`                                                                           |
| `judge`                            | 互评完成后初判；已存在初判时返回已有结果，避免重复模型调用                                                                                     |
| `discuss`                          | `text` 或 `waive: true`，当前尚未回应的幸存者；`rebut` 为兼容别名                                                                              |
| `finalize`                         | 所有幸存者完成回应后终判                                                                                                                       |

最小只读排查可用 `curl http://localhost:8787/api/health` 和目录接口；不要用真实玩家存档作破坏性测试。新增命令应同时改类型、服务/引擎、UI 和自动测试。

## 十一 持久化 撤回与兼容

地图对局保存在 `server/data/expeditions.json`。旧实验台使用 `state.json`、`judgments.json`；归档小程序的 `rooms.json` 不由地图局读写。导出含玩家姓名、评论和发言，分享前检查隐私。

普通命令复制状态→验证→执行→记录历史→事务落盘；同局串行、跨局写入共享事务，临时文件重命名。模型调用在服务阶段执行，结果再次校验；模型不能把自造资源或死亡状态写回玩家。当前只支持一个后端进程，不能依靠本地 JSON 实现多进程并发和崩溃任务恢复。

全局最多保留 20 步成功命令的撤回检查点，不是每人 20 步。一次命令附带的自动抽牌、灾难连锁和洪水扣库一起恢复。重做还原既有随机结果；撤回后重复同一操作顺序也使用恢复的随机状态。新成功操作关闭旧重做分支；失败和只读操作不关闭。学习局首份互评/跳过提交后锁定，旧局初判成功后锁定；不会通过重做再次调用模型。

`events`/`donations` 只代表当前有效分支，`historyAudit` 额外保留撤回、重做、被移出/恢复事件的记录，不将撤销行为混作上帝当前证据。版本号仍递增，UI 依 `lastChangeRevision` 清草稿。科技选择还用独立 `offerId` 区分嵌套及重复使用同 UID 的新选择，避免残留选项。

新局冻结 `balance.json` 数值、公共事件牌库/轮次与开局机会背景；不是整个程序和所有内容都被冻结。地图、卡牌处理器和全局内容改动仍需明确兼容策略。旧学习 v1 不会中途加入公共事件；无学习标记的旧局保留以下差异：

| 项目           | 无学习标记的旧局                      | 当前网页新局                      |
| -------------- | ------------------------------------- | --------------------------------- |
| 无人机         | 部署经济 +2、环境 −2；常规采集自动 +1 | 部署经济 +1；主动增产才付环境成本 |
| 补给舱         | 从使用者开始按座位领取                | 库存少者优先，同量按座位          |
| 生态崩坏       | 在场期间采过的格子不再产出            | 共享一整轮休养，r+2 恢复          |
| 互评与公共事件 | 不补插学习功能                        | 互评 + 第 2/4/6 轮公共事件        |

旧活动局有有限迁移：补共享世界/数值字段，必要时从既有日志推导洪水伤势；首次成功写操作才落盘，不用 GET 重写。已结束局与既有审判不随意改写。升级前应备份本地存档，不承诺任意未来版本无损自动迁移。

npm test                   # 全部后端：规则、HTTP、归档、Prompt、适配器模拟等

首次浏览器环境缺失时可运行 `npx playwright install chromium`；macOS 配置会优先使用已安装的 Chrome。浏览器测试启动/复用网页，接独立临时 API 和 JSON 目录，不操作真实游戏，不读取真实 key。输出限制在 `test-results/browser`，不要改回整个 `test-results`，以免自动清理其它实验档案。

2026-11-02 提交前回归结果：256 项后端测试、52 个浏览器场景全部通过，类型检查与构建通过。测试中的模型适配器使用模拟传输，本次没有调用 MiniMax；运行 `npm test` 不代表真实模型可用或判词正确。

真实 M3 批量模拟工具保留在 `scripts/simulate-learning-live.mjs` 和 `scripts/lib/`，只有显式 `--live` 才允许读取本地密钥和付费调用。默认回归不运行。其独立请求预算、断点、失败归档和结构输出试验不等于网页默认改用工具协议；网页默认仍为 JSON 裁决协议。既往实测状态和费用统计口径见真实 M3 报告，不用补造结果凑满二十局。

### 改一张卡时的检查清单

1. 先明确条件、成本、收益、响应者、次数、目标、无资源/无路/满手边界及是否影响世界。
2. 更新 `cards.json` 的实施效果、学习覆盖和 `effect-summaries.json`；原 `effect` 保留来源原文，不用改描述假装改逻辑。
3. 更新引擎和相关只读条件/预测，新增功能优先独立处理器；不能只在 UI 扣资源。
4. 同步本手册对应行及玩家提示。若改玩法影响卡面文字，新增匹配风格且不变形的版本图，保留原图和旧规则引用。
5. 增加正常、拒绝/失败、重复、阶段打断恢复、灾难组合、撤回重做与浏览器可操作性测试。
6. 跑一批固定种子 20 局，与之前规则同种子对照，记录变更、指标、失败与局限；数值校准和独立验证用不同种子。
7. 确认旧存档兼容或显式版本迁移，再提交，不把目标生存率变成每局硬保人数。

数值、洪水费用和地图不是现实模型参数。现有规则机器人结果可用于发现死锁和比较策略，不能代替真人学生试玩、教育效果研究或真实模型质量评估。

## 十三 安全边界与提交范围

`.env`、真实运行存档、学术原件、测试输出、日志不提交。`.env.example` 密钥始终留空；密钥只在服务端，不进入前端常量、Prompt、截图或测试报告。学术 PDF 当前本地归档不代表有权随商业产品分发，逐项许可见学术报告。

提交前运行文件安全检查、`git diff --check`，逐项暂存代码/数据/文档，检查暂存清单后再提交。不要用 `git add .` 混入个人资料或真实对局。单独保存原始实验产物，不让浏览器输出目录清理它们。

当前尚无远程账号鉴权、私密手牌隔离、限流、生产数据库、备份恢复和模型任务队列。CORS 与 `actor` 字段不是访问控制，不能直接对公网开放。本轮提交和手册不改变这个本地测试边界。
