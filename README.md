当前版本：**0.3.0-local**。入口：[http://localhost:3000/](http://localhost:3000/)。原世界属性与上帝调试台移至 [/lab](http://localhost:3000/lab)。

小程序及其共享房间实现已完整封存在 Git 分支 `archive/miniprogram-v0.2`（快照 `9733568`）。当前 `feature/web-hex-map` 不再导入小程序代码，也不读写旧 `rooms.json`。本轮只做本地网页，没有部署或推送。

## 快速开始

Node.js >= 22.13。首次安装：

```bash
npm ci
npm --prefix app ci
npm run dev:mock
```

打开首页，默认已选择 3 位玩家；可以选 1—6 人、10 个角色、不同出生旗子及方舟席位。点击“确认角色与旗子 · 开始航程”即可开始，本机轮流操作。

- `npm run dev:mock`：完全离线规则裁决，不调用付费模型。
- `npm run dev`：读取现有本地 `.env`，配置有效时终局使用 MiniMax；默认模型为 `MiniMax-M3.0`。
- 网页 3000，API 8787。已有服务时不要重复启动；修改模型环境配置后需重启 API。
- 刷新恢复当前局，“返回选人 / 新局”不会删除旧局；可从本地存档列表继续。
- 游戏中点击地图下方的玩家卡，可只读查看其手牌、装备、资源、位置、捐赠和世界影响；卡面可以放大。切换查看不改变回合或行动者，点击“返回当前行动玩家”恢复操作。
- 不要覆盖已有 `.env`。首次配置可手动复制空密钥模板 `.env.example`；密钥只在服务端填写。

## 已实现的模块

1. **玩家与角色**：10 张原文档角色图，1—6 人本地轮流操作，独立位置、资源、手牌、装备和累计捐赠；三属性为全员共享的世界值。
2. **六边形地图**：原图背景、规则六边形网格、六面出生旗子、资源标注、水域、三层洪水区、可达路径和角色棋子。
3. **回合行动**：出牌 → 移动 → 采集 → 上交；每步可跳过。基础移动 0—2 格，当前位置有资源且未淹没才可采集。
4. **卡堆与效果**：邀约、科技两个行动卡种；科技抽两张选一张立即生效，包含 13 种即时/持续科技；支持交换请求和对方拒绝。
5. **方舟与洪水**：个人物资转入方舟并留下捐赠记录；三次洪水逐人结算、按骰点扣方舟物资、禁用淹没格采集。
6. **全局信息**：逐操作保存回合、玩家、命令、移动路径、资源/三属性变化、手牌与装备变化、方舟变化及事件序号，可在页面查看或导出 JSON。
7. **终局上帝**：第八回合结束后审判每位玩家是否登舟，可统一提交一次申辩，保留初判与终判。服务端校验席位、资格和真实日志引用。
8. **可测试后端**：纯规则引擎、独立地图/卡牌数据、持久化服务、HTTP 层和模型适配层分离。
9. **共享世界与灾难**：三个手动滑条、调节原因留档、12 张卡的实际效果、极高/极低叠加、资源选择与生态阻止响应，全部走同一事务引擎。
10. **玩家只读查看**：将查看视角与服务端行动者分离。其他玩家详情不接收操作回调，查看期间不提供回合动作且禁用世界调节；返回当前行动者才可操作，后端仍验证每次请求的行动者和版本。

## 八回合规则

每一回合由所有玩家按座位顺序完成行动，**不是一名玩家操作一次就算一回合**。

| 回合 | 开始抽牌 | 全员行动结束后 |
| --- | --- | --- |
| 1、2 | 每人 1 张行动卡 | 进入下一回合 |
| 3 | 不抽 | 第一次洪水；结算后每人抽 1 张 |
| 4 | 不抽 | 进入下一回合 |
| 5 | 每人 1 张行动卡 | 第二次洪水 |
| 6 | 每人 1 张行动卡 | 进入下一回合 |
| 7 | 每人 1 张行动卡 | 第三次洪水 |
| 8 | 每人 1 张行动卡 | 封存回合操作，进入上帝审判 |

洪水以提供的卡面箭头为准，在第 **3、5、7 回合结束**结算：

| 洪水 | 淹没区 | 方舟扣除 | 个人扣除 |
| --- | --- | --- | --- |
| 第一次 | Zone 3 外环 | 骰定一种资源 1 份 | 木头或金属 1 份 |
| 第二次 | Zone 2 中环，外环持续淹没 | 骰定一种资源 2 份 | 种子 1 + 木头/金属/电力中 1 份 |
| 第三次 | Zone 1 内环，中外环持续淹没 | 骰定一种资源 3 份 | 电力 1 + 种子 1 + 任意其它一份资源 |

每次只投一枚六面骰：1/2 木头、3/4 金属、5/6 电力；不够扣时按余额扣除，不重新投骰、不产生负数。骰点与实际损失留档。个人选扣由当前玩家确认；固定扣除不足时只扣实际持有量。

第三次的“其它”按卡面“任意 ×1”实现为四类资源中的一份，必须在固定支出后仍有剩余。洪水不会抹掉历史捐赠贡献。

### 明确标注的本地约定

原资料未规定的细则不是最终桌游规则，可继续迭代：

- 起始资源 0，三属性各 10；每次抽 1 张行动卡；普通手牌上限 5，满手牌时新抽牌进入弃牌堆。
- 行动卡两种等概率；科技 13 种等概率；有放回、可重复。快速原型机未选卡“放回牌池”，当前不是有限、固定顺序牌堆。
- 每次采集基础 1 份；每位玩家按自己的行动计算。生态崩坏在场时，所有玩家共享采集历史，采过的资源格不可再产出；离场后解除限制。资源池四种等概率。
- 角色卡仅提供形象和阵营，不自行增加文档没有写的角色能力。
- 同格或相邻视为建立联络；相邻交换/争夺可同格执行。方舟范围为地图中心安全区域，上交材料不限位置。
- 同名持续科技不叠加；重复获得不再次加属性。全局经济、环境、社会各为 1—19，不再保存个人分数或取玩家均值。
- 淹没区不允许采集；滞留者可在下一次移动时沿向内的路径逃生，不立即死亡。安全区不能主动进入淹没区。
- 终局仍处淹没区不能登舟；席位默认最多 3 个、开局可选。未额外添加“达到 X 物资才造好方舟”的门槛。
- 三属性灾难会实际结算；未定义的保护行为由用户确认条件，不自动把采集/捐赠视为保护。“斗争”限制落实到已存在的机械爪争夺，不额外虚构一种行动卡。
- 这是本地模拟多人，不是独立账号的远程联机。所有人的手牌可由本机测试者查看。

查看视角仅保存在本页面，不写入游戏存档、不新增事件、不推进回合；刷新后默认回到当前行动者。普通模式自动跟随换人；查看其他玩家时，轮询仍更新真实行动状态但不会把查看者变成行动者。交易、洪水、灾难选择由 `pending.actor` 指定的响应玩家处理，完成后恢复原回合，不能通过点击玩家卡抢走响应权。切换查看会清空尚未提交的邀约、材料等输入，避免误用另一玩家的草稿。该控制是本地回合规则，不等同于远程账号身份认证。

### 科技实现对应

| 科技 | 当前执行效果 |
| --- | --- |
| 空间戒指 | 手牌上限 8，同类不叠加 |
| 滑板鞋 | 每回合基础移动上限 +1 |
| 名刀 | 洪水淹到玩家时额外移动最多 2 格，随后弃置 |
| 采矿无人机 | 本回合采集同类资源 +1 |
| 储备仓 | 洪水个人实际支出减免 1；优先减任选支出 |
| 炼金炉 | 消耗任意 2 份资源，换 3 份同种资源；本回合禁止邀约卡 |
| 互助信标 | 每回合与相邻玩家各交换 1 份，经对方同意；双方本回合不得彼此争夺 |
| 共享补给舱 | 公开生成玩家数 +1 份资源，从使用者起轮流各取 1，余下退回 |
| 生态驱赶器 | 方舟范围外玩家各弃 1 资源或向外移动 1；无资源且无路则记录无法执行 |
| 黑潮警报器 | 水边/河边/洪水边玩家各弃 1 资源，无资源则弃 1 手牌；都没有则记录无损失 |
| 快速原型机 | 抽 2 张行动卡选 1 入手，另一张回牌池 |
| 废墟蓝图 | 从行动弃牌堆回收 1 张，不回收已使用科技装备 |
| 回收机械爪 | 从相邻玩家随机取 1 份资源；对方无资源则自己抽 1 张行动卡 |

三属性增减保留在 `server/data/expedition/cards.json` 的 `status` 字段，随科技成功生效一次性作用于共享世界。科技可打断当前行动/洪水选择，完成效果后返回原流程；灾难资源选择和生态阻止响应期间不能插入新科技。无法满足条件时可放弃收益，不让对局卡死。

## 共享世界、手动调节与叠加灾难

一局只有一组经济、环境、社会。切换行动玩家不会改变这组数值；各局之间以及 `/lab` 与地图局之间仍是独立存档，不串局同步。玩家的 `worldImpact` 仅记录其行动对世界的累计实际影响，不是个人分数，主持人手动改分不计入任何人的贡献。

页面“共同的世界”可拖动滑条或输入数值。拖动只预览，填写原因后点击“应用世界分数并结算灾难”才提交；需要先处理完当前选择。其他操作已更新状态时必须恢复当前值后重调，避免旧草稿覆盖新状态。

| 生效分数 | 同时生效的档位 |
| --- | --- |
| 1—2 | 普通负向 + 极低，两张卡 |
| 3—6 | 普通负向，一张卡 |
| 7—13 | 稳定，无卡 |
| 14—17 | 普通正向，一张卡 |
| 18—19 | 普通正向 + 极高，两张卡 |

“正向”指分数偏高，不代表所有效果都是奖励。比如经济 18 同时触发“先发展再治理”和“财富悬殊”。进入效果按卡 ID 去重，18→19 不重复执行；18→17 只解除极高卡，普通卡不重新发奖；离开后重入才再次执行进入效果。

结算先快照同一波全部新卡，再按普通档→极端档、各档经济→环境→社会执行。分数变化继续检查连锁；已经触发的资源选择会完整结算，不因连锁离场而丢失。例如经济/环境/社会同时设为 18/10/18，会先触发四张卡，再结算为 17/8/17，最终常驻两张普通高位卡。触发与解除都有日志。

生态管制的社会 −1 是在场持续修正，不随刷新或每次动作反复扣分，离场解除。滑条修改 `world.base`，大号显示及触发阈值使用修正后的 `attributes`。因此环境 18、社会基础 18 时，社会生效值为 17，不会错误触发社会极高卡。

- 即时效果：扣科技、收回经济增益装备、世界分数变化、逐人领/扣资源、最穷者交金属。
- 持续效果：手牌上限、资源格枯竭、邻接交易限制、采集概率、生态阻止响应。
- 每轮效果：全员完成行动后、洪水之前，先强制互助再稳态漂移；进入稳态的当轮已经漂移，不在轮末重复。
- 条件效果：“资源保护”在选定资源格、填写原因后，通过“确认成功保护”或“确认开发受限”执行，分别环境 +1 或经济 −1。

用户已确认晶矿按金属、保障物资按四类现有资源自选。全部 12 张卡的落实方式、资源排行与边界约定见 [灾难规则](disaster.md)；可配置映射在 `server/data/expedition/disaster-rules.json`。

## 上帝输入与数据流程

```text
玩家动作 → 服务端规则验证 → 状态与因果事件原子保存
                                      ↓ 第八回合结束
最终状态 + 每位玩家全程操作 + 捐赠 + 洪水/交换/争夺记录
  → 随机上帝 → 数据后端完整人设 → 本地 RAG
  → M3 分析或离线规则裁决 → 校验每位玩家、席位、事件证据
  → 初判 → 一次可选申辩 → 终判 → 本地 JSON 留档
```

终局输入包含 `context.players`、`attributes`、`world`、`activeDisasters`、`ark`、`donations`、`globalEvents` 和 `policy`。不是只给三个最终分数；日志包含操作前后世界值、实际变化、手动原因、灾难触发/解除、资源流转、阻止行为与漂移骰点。

System Prompt 使用独立数据后端的完整人设。User Prompt 放入上述状态、RAG 证据、上次裁决和申辩，并要求逐玩家输出登舟与否、理由及事件序号。输入中的玩家姓名/文字只作为数据，不作为系统指令。

Prompt 修改位置：

- `server/data/gods.json`：人格元数据与文件映射；
- `server/data/god-prompts/radical.txt`、`balanced.txt`、`conservative.txt`：完整提示词。

每次模型调用前重新读取；`god.md` 仅是设计文档。按既有要求，不将 Prompt 原文、路径或哈希写入快照。

本地 RAG 仍是可替换的 Hash-256 测试嵌入模型，知识在 `server/data/knowledge.json`，不是生产级语义检索。MiniMax 未配置、超时或结构化结果非法时明确回退本地裁决。离线排序为“捐赠×3 + 合作×2 − 争夺×2 + 玩家对上帝关注维度的累计世界影响”，先排除淹没玩家，同分按座位顺序；离线申辩保留原文但不假装进行了自然语言理解。

初判与终判均保存在 `judgment.history`，检索证据和冻结的游戏上下文一并留档。世界实验台 `/lab` 仍保留原来的手动、可重复触发上帝流程；地图游戏只在终局触发，二者存档独立。

地图是“原画 + 独立规则层”，不是直接把图片像素当规则。格子是正六边形；因原画不是规则化地图数据，资源/水域/区界由人工坐标标定，可在 `map.js` 校准。P2 周围存在空地，不保证每个旗子第一步都有资源。暂未提供地图编辑器。

卡牌文字变更在 JSON；改玩法需要同步规则引擎与测试，单改文案不会自动生成新逻辑。地图和卡牌数据改后重启 API。当前为活动旧地图局提供 v1→v2 迁移：保留已保存的世界值、移除个人分数、从日志恢复采集历史；GET 只算展示，不写文件或执行奖惩，第一次成功操作才保存迁移并结算进入效果。已结束局和历史审判不改写。不承诺未来所有版本自动兼容。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/expeditions/catalog` | 地图、角色、卡堆、规则元数据 |
| GET / POST | `/api/expeditions` | 列表 / 创建新局 |
| GET | `/api/expeditions/:id` | 权威状态和合法移动范围 |
| POST | `/api/expeditions/:id/actions` | 行动、选择、洪水、审判、申辩、确认 |

行动体为 `{ type, actor, revision, ...参数 }`；例如 `{type:"move",actor:"P1",revision:2,tileId:"4,-11"}`。过期 revision 被拒绝，非法操作不会部分扣款。同一局审判重试返回已有结果，不重复调用模型。创建新局响应丢失后的跨请求防重复尚未实现，重试前可先看本地存档列表。

共享世界动作也走同一接口：`set_world` 携带 `attributes: {economy, environment, society}` 和 `reason`；`confirm_protection` 携带 `outcome: "protected" | "restricted"`、`tileId` 和 `reason`。灾难资源选择使用 `choose + resource`；生态阻止使用 `choose + block`，阻止时另给 `resource`。所有动作都需当前响应玩家与最新 `revision`。

## 测试与模拟

```bash
npm run test:game         # 新地图、全部科技、HTTP/JSON、终局上下文与素材测试
npm run test:simulation   # 一条命令完成 20 局 8 回合模拟，覆盖 1—6 人
npm run test:simulation -- 100
npm test                 # 同时回归原上帝/灾难/数据后端/模型适配
npm run typecheck
npm run build
npm run test:e2e          # 首次按需 npx playwright install chromium
npm run release:check    # 文件安全门禁 + 所有测试 + 类型 + 构建 + 浏览器
```

模拟使用固定种子，走真实规则命令；不直接篡改玩家资源来跳过游戏。专项单元测试另行构造边界状态。浏览器测试使用独立临时 HTTP 服务与 JSON 目录，不读真实密钥、不调用真实 M3、不修改用户对局。

覆盖：角色/旗子冲突、越界和重复行动、空地/洪水采集、资源守恒、拒绝交易、13 种科技、整轮互助保护、科技打断并恢复洪水、3/5/7 洪水与抽牌顺序、并发过期状态、刷新/服务重建恢复、终局初判/申辩归档、非法模型输出降级及 390px 窄屏。

新增 `expedition-world.test.js` 覆盖共享值、全部 12 张灾难、阈值叠加与去重、连锁快照、跨玩家枯竭、50% 判定、轮末时机、生态阻止、条件确认、恢复队列与旧局首操作。HTTP 测试检查重复提交只结算一次、GET 无写入、重启后继续选择和上帝证据；浏览器实际拖动滑条并检查两张卡、重载、保护确认与阻止资源扣除。

玩家查看专项验证：切换/放大卡面零 POST、无状态变化；手牌/装备/库存展示；非当前视角无操作入口、世界控件禁用；清空草稿、返回真实行动者；交易指定回应、轮询换人保持只读、刷新跟随当前玩家。HTTP 回归逐项拒绝非当前玩家的 12 类动作并验证存档字节不变。

## 存档、安全及下一轮

- 新游戏保存在 `server/data/expeditions.json`；旧 `state.json`、`judgments.json` 和已归档 `rooms.json` 不迁移、不删除。
- 每个动作原子保存，不在浏览器自行判定资源；页面可导出本局完整 JSON。存档包含玩家文字，分享导出文件前自行检查。
- `.env`、运行 JSON、浏览器测试产物均忽略；公开 `.env.example` 的密钥保持空白。不会把密钥放进前端或模型提示词。
- 仅支持本地、单进程受控测试；无公网账号鉴权、对局权限、限流、数据库备份恢复或模型任务崩溃恢复，不可直接开放公网。
- 下一轮优先确认手牌/席位/资源与缩圈细则并校准地图；随后拆分更细的卡牌处理器、增加地图编辑器和版本迁移，再考虑远程联机。

旧手机版的历史实现、测试结果和文档均可在归档分支查看，不代表当前网页版本的行为。
