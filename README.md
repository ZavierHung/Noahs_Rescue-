## 快速开始

Node.js >= 22.13。首次安装：

```bash
npm ci
npm --prefix app ci
npm run dev:mock
```

打开首页，默认已选择 3 位玩家；可以选 1—6 人、10 个角色及不同出生旗子。方舟容量由库存计算，不再开局手动指定。点击“确认角色与旗子 · 开始航程”即可开始，本机轮流操作。

- `npm run dev:mock`：完全离线规则裁决，不调用付费模型。
- `npm run dev`：读取现有本地 `.env`，配置有效时终局使用 MiniMax；默认模型为官方 ID `MiniMax-M3`，旧配置 `MiniMax-M3.0` 自动兼容为同一 M3 型号，不切换套餐或模型系列。
- 网页 3000，API 8787。已有服务时不要重复启动；修改模型环境配置后需重启 API。
- 刷新恢复当前局，“返回选人 / 新局”不会删除旧局；可从本地存档列表继续。
- 游戏中点击地图下方的玩家卡，可只读查看其手牌、装备、资源、位置、捐赠和世界影响；卡面可以放大。切换查看不改变回合或行动者，点击“返回当前行动玩家”恢复操作。
- 不要覆盖已有 `.env`。首次配置可手动复制空密钥模板 `.env.example`；密钥只在服务端填写。

## 八回合规则

每一回合由所有玩家按座位顺序完成行动，**不是一名玩家操作一次就算一回合**。

| 回合 | 开始抽牌 | 全员行动结束后 |
| --- | --- | --- |
| 1、2 | 每人 1 张行动卡 | 进入下一回合 |
| 3 | 不抽 | 第一次洪水；结算后每人抽 1 张 |
| 4 | 不抽 | 进入下一回合 |
| 5 | 每人 1 张行动卡 | 第二次洪水 |
| 6 | 每人 1 张行动卡 | 进入下一回合 |
| 7 | 每人 1 张行动卡 | 第三次洪水 |
| 8 | 每人 1 张行动卡 | 轮末灾难 → 受困者最后撤离 → 种子救生与生存结算 → 登船审议 |

洪水以提供的卡面箭头为准，在第 **3、5、7 回合结束**结算：

| 洪水 | 淹没区 | 方舟扣除 | 个人扣除 |
| --- | --- | --- | --- |
| 第一次 | Zone 3 外环 | 骰定一种资源 1 份 | 木头或金属 1 份 |
| 第二次 | Zone 2 中环，外环持续淹没 | 骰定一种资源 2 份 | 种子 1 + 木头/金属/电力中 1 份 |
| 第三次 | Zone 1 内环，中外环持续淹没 | 骰定一种资源 3 份 | 电力 1 + 种子 1 + 任意其它一份资源 |

每次只投一枚六面骰：1/2 木头、3/4 金属、5/6 电力；不够扣时按余额扣除，不重新投骰、不产生负数。骰点与实际损失留档。个人选扣由当前玩家确认；固定扣除不足时只扣实际持有量。

第三次的“其它”按卡面“任意 ×1”实现为四类资源中的一份，必须在固定支出后仍有剩余。洪水不会抹掉历史捐赠贡献。

洪水到来时自动定位结算面板。先看方舟本次骰点、应扣与实际扣除，再为当前玩家选择额外物资、核对实际合计，点击确认才扣个人资源。储备仓减免、库存不足及无可扣物资均明确提示；方舟不会随每位玩家确认重复扣除。木头、金属、电力、种子统一使用 SVG 图标和数量，覆盖地图标记、库存、交换、捐赠与资源选择，保留中文无障碍标签和悬停说明。

### 新版邀约：共同领取，不是交换

点击手牌的“使用”后，页面自动定位到“邀约卡 · 选择同伴与资源”：发起者选同伴和自己想要的资源 → 对方选择自己想要的资源并接受 / 拒绝 → 双方领取并返回原玩家。

- “最近两个玩家”本版解释为：以发起者为中心，按地图物理直线距离排序的两名其他玩家；并非六边形相邻一格，也不是全场唯一的最近一对。距离相同按座位号稳定排序；不足两人则取全部其他玩家。
- 双方各从公共资源池新获得一份自选资源，可选不同种类，零库存也可使用。接受时重新检查距离排名、邀约卡与炼金炉限制，原子发放并消耗邀约卡；拒绝不发资源、不消耗卡牌，可重试。
- 等待回应时刷新仍恢复原请求；只读查看不能接受或拒绝。请求、接受/拒绝及实际影响留在全局日志中；完成后恢复发起者的行动步骤。
- 互助信标是独立科技，仍要求同格/相邻一格与现有库存，每人各交换一份、每回合一次。社会失序限制交易，不阻止新版邀约的公共领取。旧存档中已经提出的交换请求按原约定完成，不把待响应合同改成免费领取。

### 撤回、重做与修正留档

游戏顶部的「行动修正」可撤回最近 **20 步成功操作**，也可逐步重做。点击按钮先显示操作玩家、回合及操作内容，再明确确认；取消或 Esc 不改变存档。只读查看其他玩家时不可操作。这里是**全局撤回栈**，不是每人独立的悔棋：由当前行动/响应玩家确认，允许跨玩家、跨回合恢复；撤回后跟随恢复出的行动者。

- 一步指一次成功的服务端命令，其自动抽牌、回合推进、洪水扣库、灾难连锁等效果一起恢复。已接受邀约可恢复成等待受邀人回应，双方资源与消耗卡同时回退；再撤回发送则取消邀约。
- 资源、卡牌、位置、伤势、生存、方舟库存与捐赠、共享世界和待处理队列一并恢复。只取消 UI 草稿不产生历史；失败请求也不生成历史。
- 重做恢复原结果，不重新抽牌或投骰；撤回后重复相同的随机操作/顺序使用原随机状态。执行新的游戏操作会关闭旧重做分支；只读查看、刷新、失败请求不会关闭。
- 第 8 回合结算后、初次审议前仍可撤回。上帝初判成功后锁定所有游戏历史，发言、最终名单不可撤回；失败的审议不提前锁定，也不会因重做调用模型。
- 刷新和 API 重启保留历史。旧局从更新后的第一步成功操作开始记录，不能追溯撤回更新前的操作。存档仍为 Git 忽略的本地 `expeditions.json`，不覆盖旧局。
- `events` 与 `donations` 代表当前有效分支，只有这些进入上帝证据。`historyAudit` 单独保留撤回、重做和分支关闭记录，包括被移出/恢复的事件；可在「撤回与重做记录」查看，导出 JSON 也包含。归档事件序号须结合修正的版本号解读，不当作当前事件编号。

实现独立放在 `server/src/expedition/history.js`：保存有界的完整可变状态检查点，追加型事件日志只存每步增量，不重复保存整份日志，也不递归嵌套历史。API 不返回内部 `historyState`、恢复快照或随机种子；`history` 仅返回可操作摘要。`revision` 每次撤回/重做也递增，仍由每局串行队列和写入事务防止双击、过期请求及部分恢复。撤回需要当前玩家的 `actor`，沿用本地轮流模拟的回合校验，**不是远程账号鉴权**。

本地调试允许撤回已看过的牌；这不是竞技模式的防作弊机制。未来联网版需另加多人同意、隐藏信息边界、历史分页/归档及数据库事务；当前审计记录持续保留，JSON 只适用于单进程小规模本地使用。

### 生存与方舟容量：当前数值版

数值集中在 `server/data/expedition/balance.json`，修改后重启 API；新局保存规则快照，改配置不会改变已有新版本对局。配置载入时校验整数范围和非零除数。当前默认：

| 项目 | 数值与时机 |
| --- | --- |
| 常规移动 / 采集 | 每回合最多 2 格 / 基础 1 份；科技加成另计 |
| 洪水欠缴伤势 | 减免后应缴量减实际缴纳量，每缺一份积累 1 点，不产生负库存 |
| 最后撤离 | 第 8 回合轮末灾难结束后，仍在淹没区者各有一次最多 1 格向内移动；可原地，不再出牌、采集或捐赠 |
| 种子救生 | 撤离后个人保留的种子自动消耗，最多每份恢复 1 点累计伤势，最多消耗至伤势归零 |
| 生存条件 | 位置安全且恢复后伤势 ≤ 5；统一在终局结算，游戏中欠缴为累积伤势而非立即死亡 |
| 方舟容量 | `min(玩家数, 6, floor(方舟实际物资总份数 / 17))`；四种物资各计一份，含种子补给；最低可为 0 |

这是可迭代的抽象建造/补给规则，暂不要求每席固定的材料配比。容量随捐赠增加、洪水扣库减少；历史贡献保留但不能替代实际库存。席位计算不再消耗一次库存，上帝不能扩大容量。保留种子救生与捐给方舟之间存在取舍，不用随机淘汰或预定名单凑目标比例。

### 明确标注的本地约定

原资料未规定的细则不是最终桌游规则，可继续迭代：

- 起始资源 0，三属性各 10；每次抽 1 张行动卡；普通手牌上限 5，满手牌时新抽牌进入弃牌堆。
- 行动卡两种等概率；科技 13 种等概率；有放回、可重复。快速原型机未选卡“放回牌池”，当前不是有限、固定顺序牌堆。
- 每次采集基础 1 份；每位玩家按自己的行动计算。生态崩坏在场时，所有玩家共享采集历史，采过的资源格不可再产出；离场后解除限制。资源池四种等概率。
- 角色卡仅提供形象和阵营，不自行增加文档没有写的角色能力。
- 互助信标交换/机械爪争夺按同格或相邻格执行；邀约例外，使用最近两名玩家规则。方舟范围为地图中心安全区域，上交材料不限位置。
- 同名持续科技不叠加；重复获得不再次加属性。全局经济、环境、社会各为 1—19，不再保存个人分数或取玩家均值。
- 淹没区不允许采集；滞留者可在下一次移动时沿向内的路径逃生，不立即死亡。安全区不能主动进入淹没区。
- 终局未存活者不能登舟；是否存活由上述位置和伤势规则决定，不由模型决定。容量按实际物资计算。
- 三属性灾难会实际结算；未定义的保护行为由用户确认条件，不自动把采集/捐赠视为保护。“斗争”限制落实到已存在的机械爪争夺，不额外虚构一种行动卡。
- 这是本地模拟多人，不是独立账号的远程联机。所有人的手牌可由本机测试者查看。

查看视角仅保存在本页面，不写入游戏存档、不新增事件、不推进回合；刷新后默认回到当前行动者。普通模式自动跟随换人；查看其他玩家时，轮询仍更新真实行动状态但不会把查看者变成行动者。交易、洪水、灾难选择由 `pending.actor` 指定的响应玩家处理，完成后恢复原回合，不能通过点击玩家卡抢走响应权。切换查看会清空尚未提交的邀约、材料等输入，避免误用另一玩家的草稿。该控制是本地回合规则，不等同于远程账号身份认证。

### 科技实现对应

| 科技 | 当前执行效果 |

| 空间戒指 | 手牌上限 8，同类不叠加 |
| 滑板鞋 | 每回合基础移动上限 +1 |

| 黑潮警报器 | 水边/河边/洪水边玩家各弃 1 资源，无资源则弃 1 手牌；都没有则记录无损失 |
| 快速原型机 | 抽 2 张行动卡选 1 入手，另一张回牌池 |
| 废墟蓝图 | 从行动弃牌堆回收 1 张，不回收已使用科技装备 |
| 回收机械爪 | 从相邻玩家随机取 1 份资源；对方无资源则自己抽 1 张行动卡 |

三属性增减保留在 `server/data/expedition/cards.json` 的 `status` 字段，随科技成功生效一次性作用于共享世界。科技可打断当前行动/洪水选择，完成效果后返回原流程；灾难资源选择和生态阻止响应期间不能插入新科技。无法满足条件时可放弃收益，不让对局卡死。

15 张卡均增加 `implementedEffect` 明确本版执行语义，卡面原文 `effect` 和图片不覆盖；网页卡面预览、科技选择和只读卡牌详情优先显示本版规则。终局撤离和审议阶段禁止再用科技。重复被动不叠加也不重复加分；公开补给按座位轮流领取；回收只取实际行动弃牌；原型机的“牌堆底”在有放回模式中解释为回到随机池。详见卡牌 JSON 和各项规则测试。

## 共享世界、手动调节与叠加灾难

一局只有一组经济、环境、社会。切换行动玩家不会改变这组数值；各局之间以及 `/lab` 与地图局之间仍是独立存档，不串局同步。玩家的 `worldImpact` 仅记录其行动对世界的累计实际影响，不是个人分数，主持人手动改分不计入任何人的贡献。

页面“共同的世界”可拖动滑条或输入数值。拖动只预览，填写原因后点击“应用世界分数并结算灾难”才提交；需要先处理完当前选择。其他操作已更新状态时必须恢复当前值后重调，避免旧草稿覆盖新状态。

| 生效分数 | 同时生效的档位 |
| --- | --- |
| 1—2 | 普通负向 + 极低，两张卡 |
| 3—6 | 普通负向，一张卡 |
| 7—13 | 稳定，无卡 |
| 14—17 | 普通正向，一张卡 |
| 18—19 | 普通正向 + 极高，两张卡 |

“正向”指分数偏高，不代表所有效果都是奖励。比如经济 18 同时触发“先发展再治理”和“财富悬殊”。进入效果按卡 ID 去重，18→19 不重复执行；18→17 只解除极高卡，普通卡不重新发奖；离开后重入才再次执行进入效果。

结算先快照同一波全部新卡，再按普通档→极端档、各档经济→环境→社会执行。分数变化继续检查连锁；已经触发的资源选择会完整结算，不因连锁离场而丢失。例如经济/环境/社会同时设为 18/10/18，会先触发四张卡，再结算为 17/8/17，最终常驻两张普通高位卡。触发与解除都有日志。

生态管制的社会 −1 是在场持续修正，不随刷新或每次动作反复扣分，离场解除。滑条修改 `world.base`，大号显示及触发阈值使用修正后的 `attributes`。因此环境 18、社会基础 18 时，社会生效值为 17，不会错误触发社会极高卡。

- 即时效果：扣科技、收回经济增益装备、世界分数变化、逐人领/扣资源、最穷者交金属。
- 持续效果：手牌上限、资源格枯竭、邻接交易限制、采集概率、生态阻止响应。
- 每轮效果：全员完成行动后、洪水之前，先强制互助再稳态漂移；进入稳态的当轮已经漂移，不在轮末重复。
- 条件效果：“资源保护”在选定资源格、填写原因后，通过“确认成功保护”或“确认开发受限”执行，分别环境 +1 或经济 −1。

用户已确认晶矿按金属、保障物资按四类现有资源自选。全部 12 张卡的落实方式、资源排行与边界约定见 [灾难规则](disaster.md)；可配置映射在 `server/data/expedition/disaster-rules.json`。

## 上帝输入与数据流程

```text
玩家动作 → 服务端规则验证 → 状态与因果事件原子保存
                                      ↓ 第八回合结束
最后撤离 → 种子救生 → 确定幸存者 / 物资容量 → 冻结游戏证据
最终状态 + 每位玩家全程操作 + 捐赠 + 洪水/邀约/交换/争夺记录
  → 随机上帝 → 数据后端完整人设 + 新职责约束 → 本地 RAG
  → M3 分析或离线规则裁决 → 校验幸存资格、容量、真实事件证据
  → 初步名单 → 每位幸存者发言或明确放弃 → 上帝回应 / 暂定名单
  → 全员交互完毕 → 上帝敲定最终名单 → 本地 JSON 留档
```

终局输入包含 `context.players`、`attributes`、`world`、`activeDisasters`、`ark`、`donations`、`globalEvents` 和 `policy`。不是只给三个最终分数；日志包含操作前后世界值、实际变化、手动原因、灾难触发/解除、资源流转、阻止行为与漂移骰点。

System Prompt 使用独立数据后端的完整人设，并追加新版登船职责，覆盖旧人设中的奖惩任务。User Prompt 放入游戏状态、RAG、当前阶段 `initial/discussion/final`、发言者、初步结果及全部 `conversations`，要求逐玩家输出登舟与否、理由和真实事件序号。玩家姓名/文字只是数据。每名幸存者一轮发言或明确放弃，按座位顺序；未完成全员回应时服务端拒绝终判，零幸存者则无需虚构对话。中途刷新可继续。

Prompt 修改位置：

- `server/data/gods.json`：人格元数据与文件映射；
- `server/data/god-prompts/radical.txt`、`balanced.txt`、`conservative.txt`：完整提示词。
- `server/data/prompts/boarding-role.txt`：当前登船职责、初判/讨论/终判阶段及不可越权边界。
- `server/data/prompts/academic-reading.txt`：学术材料使用、行为分析与引用要求。

每次模型调用前重新读取；`god.md` 仅是设计文档。按既有要求，不将 Prompt 原文、路径或哈希写入快照。

网页版学术库在 `server/data/academic/library.json`，当前 `academic-zh-v2.0` 共 22 份，采用中文关键词、中英文术语映射＋Hash-256 弱辅助，不是生产级语义模型。每次初判、申辩、终判重新检索，兼顾人设与三领域，在相关材料中补充教材基础和研究背景，不强塞无关书籍。修改资料库后重启 API；每阶段的文献、查询、版本和资料库哈希保存在 `judgment.history[].rag`，与提示词快照无关。旧 `knowledge.json` 虚构测试材料仅供 `/lab`，不进入新版登船流程。

教材包括曼昆、CORE、Perman、环境科学、社会学、社会心理学、伦理学等来源；记录版次、概念、局限和许可，中文为编者独立概念说明，非整书翻译。课程指南独立分类，同书不同章节不重复计数。13 份 PDF 已本地归档（其中曼昆为配套讲义、Perman 为样章），另 8 份网页章节和 1 份较大作者 PDF 保留外部原文链接，界面明确标注未本地归档。原件不加入 Git，新机器运行归档命令；外链条目不会被误报为 PDF 下载失败。商用发行需逐项复核许可。

本机使用系统代理时运行 `npm run knowledge:archive:proxy`；启动服务可用 `npm run dev:proxy`（先正常停止已运行的开发服务，避免重复启动）。启动器优先尊重已有 HTTP(S)_PROXY，否则继承 macOS 手动代理；只影响当前进程，不改系统配置或 `.env`，不硬编码本机地址，也不转换 PAC/SOCKS。需要支持 `--use-env-proxy` 的 Node，本轮使用 Node 25.7.0。此前下载超时的原因是终端没有继承系统代理，并非用户网络不可用。

可选真实模型冒烟测试：`npm run test:knowledge:live:proxy -- --live`（直连用 `test:knowledge:live`）。仅显式 `--live` 才读取本地密钥、发送最多两次 M3 请求，可能消耗套餐额度；模拟六人对局，只测初判与一次申辩，不写实际存档、不自动终判。默认回归不运行这个命令。机器校验通过不保证解释准确，人工抽查及已知问题见 [学术报告](docs/ACADEMIC_KNOWLEDGE_REPORT.md)。

模型通过 `learning[]` 关联当次文献 ID、具体行为与真实事件。引用非法、领域缺失或名单越权均回退。MiniMax 未配置或超时也明确回退；离线排序仍为“捐赠×3 + 合作×2 − 争夺×2 + 玩家对上帝关注维度的累计世界影响”，排除未存活者，同分按座位顺序且受容量限制。合作含邀约与信标交换。离线模式显示阅读提示，但不假装理解申辩、不因未核实陈述加分；真实 M3 可依据完整交互修订名单。

`context.facts` 从同一冻结证据生成按玩家整理的捐赠、科技次数/先后、实际世界变化、合作双方和生存记录，减少长日志中的归属混淆；不是排名公式，也不能自动证明自然语言正确。新事件在提交时切断与装备等可变状态的共享引用，防止后续行动污染早期快照；已有用户历史不自动重写。学术输出示例显式包含 `learning`，与后端引用校验保持一致。

各阶段名单保存在 `judgment.history`，逐人问题、原话、放弃状态、上帝回应与模型/回退标记保存在 `judgment.conversations`，检索证据和冻结上下文一并留档。服务层对每阶段结果重新校验，模型输出无法修改资源、容量或生存状态。世界实验台 `/lab` 是独立的旧版调试流程，不是当前地图游戏的职责或规则。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/expeditions/catalog` | 地图、角色、卡堆、规则元数据 |
| GET / POST | `/api/expeditions` | 列表 / 创建新局 |
| GET | `/api/expeditions/:id` | 权威状态和合法移动范围 |
| POST | `/api/expeditions/:id/actions` | 行动、选择、洪水、审判、申辩、确认 |

行动体为 `{ type, actor, revision, ...参数 }`；例如 `{type:"move",actor:"P1",revision:2,tileId:"4,-11"}`。过期 revision 被拒绝，非法操作不会部分扣款。同一局审判重试返回已有结果，不重复调用模型。创建新局响应丢失后的跨请求防重复尚未实现，重试前可先看本地存档列表。

修正同样使用 `POST /api/expeditions/:id/actions`，如 `{type:"undo",actor:"P2",revision:42}` 或 `{type:"redo",actor:"P1",revision:43}`。`actor` 必须取**修正前**状态的 `activePlayerId`，不能用被撤回操作的原发起者代替。过期版本返回 409；没有历史、非当前行动者或已经开始审议返回 400，均不修改状态。GET 的 `history.undo/redo` 为下一步摘要，`undoCount/redoCount` 为剩余步数，`lastChangeRevision` 用于清除回退后的界面草稿。

共享世界动作也走同一接口：`set_world` 携带 `attributes: {economy, environment, society}` 和 `reason`；`confirm_protection` 携带 `outcome: "protected" | "restricted"`、`tileId` 和 `reason`。灾难资源选择使用 `choose + resource`；生态阻止使用 `choose + block`，阻止时另给 `resource`。所有动作都需当前响应玩家与最新 `revision`。

新版邀约：`play + cardUid + targetId + resource`，对方 `choose + accept:true + resource` 或 `accept:false`。终局撤离：`evacuate + tileId`。登船流程：`judge` 初判，依次由 `activePlayerId` 提交 `discuss + text` 或 `discuss + waive:true`，`reviewRemaining` 为空后 `finalize` 调用最终审议。旧动作名 `rebut` 仅作为单人讨论别名，不再一次结束全局。

### 六人局平衡实验 · 2026-10-29

统计分母都是每局初始 6 人：生存率 = 幸存人数 / 6，登船率 = 最终登船人数 / 6（不是幸存者中的登船比例）。配置在独立验证前冻结，不强制每局留下固定人数。离线裁决按真实日志排序，在生存与容量上限内填充席位；真实模型允许空缺。

| 实验 | 种子 / 局数 | 生存率 | 登船率 |
| --- | --- | --- | --- |
| 首轮校准候选：耐受 4、每席 18 份 | 1—100 / 100 局 | 77.50% | 49.17% |
| 首轮独立验证（未达目标范围，转为迭代依据） | 10001—10300 / 300 局 | 74.06% | 46.17% |
| 最终独立验证：耐受 5、每席 17 份 | 20001—20500 / 500 局 | **81.40%** | **50.97%** |
| 策略对照：全员捐空库存 | 30001—30040 / 40 局 | 60.42% | 57.50% |
| 策略对照：全员谨慎保留物资 | 30001—30040 / 40 局 | 90.83% | 37.92% |

最终验证共 3,000 个玩家席次，2,442 人存活、1,529 人登船；平均每局 4.884 人存活、3.058 人登船，物资容量均值 3.066 人。按独立对局比例计算的 95% 正态近似区间：生存率 80.17%—82.63%，登船率 50.09%—51.85%。这是接近 80% / 50% 的结果，不是精确保证。质量门禁目前允许目标上下 5 个百分点。

主实验固定为每局两名慷慨捐赠、两名均衡储备、两名谨慎储备机器人，随种子轮换座位；全部走真实命令，不偷看未来牌/骰子。各策略都向内移动、使用邀约和科技，区别主要在洪水与终局前保留物资。保留种子能提高个人生存，却减少船上库存；策略对照说明真人选择会显著影响结果。对 1—5 人与真实 M3 名单不承诺相同目标率。

结构化汇总、失败迭代和配置快照见 [docs/balance-results.json](docs/balance-results.json)。`test:balance` 不读取密钥、不调用真实 M3、不写实际对局；另有 20 局走真实服务的完整初判/逐人交互/终判模拟及浏览器回归。完整逐局生成结果在被 Git 忽略的 `test-results/balance-final-validation.json`，可用上方命令复现。
